[GitHub job 136934789590](https://github.com/oioio-space/inkwell/actions/runs/44933423541/job/136934789590) recorded `p2p: lobby: close called for canceled stream` during the `Rejoindre` action in ZZ-1 and the SHEET-MU-02 delete/paste/sort/fill scenario. The traces show that the peers already reported `Synchronisé`, so the pairing helper proceeded with Bob's share dialogue still open. The dialogue intercepted the history toggle and the grid cell clicks respectively. SAV-03b and SHEET-MU-01b passed in the same job.

The lobby host reads a length-prefixed request and can send the response and close its receive half immediately. The pinned libp2p QUIC implementation sends STOP_SENDING when it closes that half. If STOP_SENDING arrives before the caller's `CloseWrite`, quic-go rejects the half-close while the reply is still readable. Read the bounded response after the framed write, then close the stream. Reset on failure or context cancellation. The wire format and deadlines follow the existing [lobby specification](../protocol/spec.md#82-inkwelllobby100-existant). [RFC 9000 §3.5](https://www.rfc-editor.org/rfc/rfc9000.html#section-3.5), [pinned libp2p QUIC stream](https://github.com/oioio-space/go-libp2p/blob/cae49c803966/p2p/transport/quic/stream.go), [quic-go v0.64.1 send stream](https://github.com/quic-go/quic-go/blob/v0.64.1/send_stream.go#L590-L609).

`TestLobbyReadsReplyAfterHostStopsReceiving` delivers this ordering without timing dependencies. It failed on the original exchange with the CI error and passed after the fix. Existing tests still check refusals and response size limits.

## W77 follow-up on the lobby connection

On `21eb2e9`, [GitHub job 137347215053](https://github.com/oioio-space/inkwell/actions/runs/45067621739/job/137347215053) reported a **local** QUIC connection close (code `0x0`) while `TestOpenWindow` read the reply. Holding the caller's old sync opening result after the host rejected its connection (`ConnGated`, code `0x1007`) let the next request reach the host on a new connection. Releasing that result made `openOut` call `ClosePeer` on the caller and close the new connection before the reply. A real invitation can hit the same ordering when a refused connection is replaced. The pinned fork maps QUIC application close errors to `network.ConnError`, and `ClosePeer` closes the connections present at the time of the call. [QUIC error mapping](https://github.com/oioio-space/go-libp2p/blob/6de4a5e06d73/p2p/transport/quic/stream.go), [swarm close](https://github.com/oioio-space/go-libp2p/blob/6de4a5e06d73/p2p/net/swarm/swarm.go).

Treat a connection error from the outbound sync opening as the loss of that connection. A live connection whose opening was held back by the old one can now open its own sync stream. Stream refusal, protocol violation and the ACK budget still use the existing peer-close rule.

The controlled QUIC reproduction and `TestOpenOutConnectionLossPreservesReplacement` each went from 5 failures in 5 runs to 0 in 5. The original `TestOpenWindow` had zero failures in 50 race and 50 coverage iterations both before and after the fix.
