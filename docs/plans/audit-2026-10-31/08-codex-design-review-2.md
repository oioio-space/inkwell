# Revue Codex n°2 de la conception d'admission révisée (2026-10-31)

1. **OPEN · Critique** — `design-admission.md` (D), §2: numbered slots do **not** bound lifetime IDs when equivocation replaces winners; hash-addressed G-Set storage also retains every conflicting token. Amend: derive one immutable document ID per project/writer/kind/slot, bound evidence retention, and test repeated equivocation across restarts.
2. **PARTIAL · Critique** — D §3.6; `CollectionSynchronizer.js:107`: holding an unknown document prevents the `Repo.find` that would initialize it; Stage 1 has no pull replicator. Amend: explicitly bootstrap through a bounded loader and drain at **ready/requesting/unavailable**, with cancellation rechecked after asynchronous work.
3. **PARTIAL · Critique** — D §5/§8; ADR 0030 §4: Stage 1 can merge as incremental mitigation, but remains vulnerable to the documented writer panic/storage corruption. “Majeur, temporary” does not grade that exposure correctly. Amend: record **Critique** residuals until Stage 2; forbid claiming S1 closed earlier.
4. **PARTIAL · Critique** — D §2/§7 test 10: signatures isolate numbered quotas against forging another writer, but shared document IDs allow one writer’s equivocation to affect another writer’s referenced document. Amend: bind IDs to slots and test cross-writer aliasing; exhausting honest slots must remain impossible.
5. **PARTIAL · Critique** — D §2 “Foreign documents”: signing a foreign document ID for this project satisfies the stated verifier; project-bound signatures establish authorization, not document provenance. Amend: enforce project-derived IDs and copy imports into those IDs; explicitly sign the complete canonical tuple.
6. **CLOSED at design level · Écarté** — D §2 items 4–5 resolves Go-owned admission, project epochs, and refused-attestation retry. Amendment: require every delayed notice/refusal/queue callback to verify the active epoch; test switching projects while those callbacks are pending.
7. **CLOSED at design level · Écarté** — D §3.5; `Repo.js:250`, `CollectionSynchronizer.js:40`: forced metadata without `storageId`, plus `isEphemeral`, skips sync-state persistence/loading. Amendment: preserve the delayed-save contract test and enforce cleanup before any Repo attaches.
8. **CLOSED at design level · Écarté** — D §3.4/§7 tests 5–6 fixes asymmetric session restart and counter reuse. Amendment: qualify the memory bound as **lifetime peers × adapter instances**; `NetworkSubsystem.js:53` retains old session keys, so repeated adapter recreation needs a lifecycle limit or pruning.
9. **PARTIAL · Critique** — D §3.6/§4; `Repo.js:715`: `removeFromCache` deletes only when `handle.doc()` exists; unavailable handles remain cached. Hostile holders can also prevent “synced with every holder.” Amend: enforce an unconditional residency policy, bounded waiting, and unavailable-handle eviction; document count alone never bounds document bytes.
10. **PARTIAL · Mineur** — D §7 adds useful tests, but lacks equivocation floods, suspended-writer tokens, unknown-handle bootstrap, unavailable eviction, and multi-peer overflow fairness. Amendment: add those cases and measure RSS/WASM retention; `bench-sync/mem2.mjs` measures loaded Automerge values, not complete Repo handles and synchronizers.
11. **PARTIAL · Mineur** — D §1.1; `bench-sync/reconnect.mjs:29`: reproduced 148/12,623 B at 10,000 changes, but timing includes clones, uses one append-only actor, and lacks repeated statistical comparison. Amendment: treat 1.25 B/change as workload-specific; replace the universal 2 µs claim with repeated real-Repo reconnect/eviction benchmarks including coverage, guard, and transport.
12. **OPEN · Critique** — D §2 `EverWriter` accepts newly signed tokens after suspension/removal; test 10’s “blocks new ones” contradicts verification. ADR 0030 §2 separates historical admission from standing through causal frontiers. Amendment: specify equivalent listing/member causality and revocation semantics, preserving witnessed history while rejecting post-cut issuance; local UI checks cannot enforce this.
13. **OPEN · Critique** — D §2/§4; ADR 0030 §2–3: purge decisions address **node IDs**, listings address **document IDs**, and no authenticated mapping or purge notice is specified. Grow-only metadata can coexist with deletion, but does not reclaim document history, restore slots, or prevent replay resurrection. Amendment: define mapping, tombstones, replay suppression, disk GC, and lifetime quota exhaustion explicitly.
14. **PARTIAL · Critique** — D §3.6: ~65 MiB/peer and ~128 MiB globally bound queued payloads, not transient decoding/copies or total laptop RSS. A sender can repeatedly trigger resets; global saturation can deny honest peers. `DocSynchronizer.js:217` also retains sync states, so reset is not literally fresh. Amendment: reserve fair per-peer capacity, retain cooldown across reconnects, bound processing work, and measure peak RSS/recovery.
15. **CLOSED conditionally · Écarté** — D §2/§7 Stage 3; `CLAUDE.md` invariants and ADRs 0002/0011: `internal/listing` has a coherent admission role and a concrete Stage-3 consumer; opaque Automerge content and signed membership remain authoritative. Amendment: ratify ADR 0031, keep policy composition in application wiring, defer node support until needed, and provide a listing-based fallback row so deleting presentation metadata cannot silently hide admitted content.
