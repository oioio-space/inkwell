# Scenario 8 invitation failure

2026-11-21 · SB2a1 integration blocker, tracked under CL1 R-1.

## GitHub evidence

The candidate's editor run for seed 20774 failed on the second invitation, from Carol to Bob.
Alice's invitation completed. Playwright's request trace shows HTTP 422 from Bob's Wails binding
after 48.3 ms. Bob's server log shows the underlying lobby read failed because the connection
closed locally with yamux code 0. The page then stayed at `Seul` throughout the existing 60 s
assertion. Alice and Carol retained their direct link. Both later tried to send to Bob and
logged `transport: unknown peer`. The public peer ID derived from Bob's fixture key matches
those warnings. The test stopped before typing or the relay cut, with C1–C5 unmeasured.
The reader variant passed all five clauses in 151 s.
[Candidate netsim job](https://github.com/oioio-space/inkwell/actions/runs/44067599148/job/133985226346).

The invitations in the captured trace advertised only Carol's loopback and circuit addresses.
Inkwell forces private reachability when relays are configured.
The pinned libp2p address manager removes public addresses under private AutoNAT v1
reachability once it has relay addresses. In that configuration the invitation can exercise
the product's normal relay path even when the host has a direct address.
[Pinned libp2p address selection](https://github.com/oioio-space/go-libp2p/blob/cae49c8039665b01189b9f1e039d399dbadd665a/p2p/host/basic/addrs_manager.go#L448-L475).

Yamux uses this error for normal local session shutdown. Its implementation closes all
streams on that session. This narrows the investigation to the closure of Bob's lobby
connection. [Yamux error definition](https://github.com/libp2p/go-yamux/blob/v5.1.0/const.go#L27-L37),
[yamux session shutdown](https://github.com/libp2p/go-yamux/blob/v5.1.0/session.go#L281-L339).

## Admission after a lost response

`Host.redeem` consumes the ticket, then `Host.admit` signs the membership operation
before writing Welcome. The joiner can fail after the host has committed membership.
The same ticket is then refused even when the original device reconnects. This is
the lost-response case of IV1's existing concern about durable admission before the
join reply. The ordering follows the current one-use invitation contract.
[Protocol §8.2](../protocol/spec.md#82-inkwelllobby100-existant).
[Invitation review](../reviews/2026-11-14-ultrareview-admission-invite.md).

The out-of-tree Go witness runs the real invitation host and joiner with the existing
fake clock and drops only the first Welcome after the host has committed Bob's writer
role. It retries with the same authenticated device while the ticket is still fresh.
It failed ten times out of ten under `-race` at the retry assertion with `invite: the
invitation is not valid`. This proves the recovery gap independently of the caller
that closed the circuit in CI. The witness is in `lost-welcome-test.txt` and its output
is in `lost-welcome-red.log` under the evidence directory.

There are two separate decisions if the investigation changes the protocol:

- Preserve the lobby on a sync failure that leaves its connection usable. This
  needs a matching close stack first, then a controlled-time witness that holds the
  lobby in flight. The rule for genuine sync refusal and revocation must still keep
  an unwanted peer from reconnecting indefinitely.
- Make a committed redemption recoverable by the same authenticated device until
  expiry, with replay refusal for every other device and no second signed Add.
  This needs a decision on durable replay state and cleanup. A protocol with a
  separately acknowledged admission is a broader IV1 option that must specify
  what either side retries when the final acknowledgment is lost.
