# I18N1 — several interface languages (W88)

Rigour: **standard** (I18N1-a…c); **complete** for I18N1-d only if extension catalogs arrive inside a synced project
(peer bytes). Owner request W88 (2026-11-25), with two addenda the same day: the interface side (characters, word
length) is first-class, and the proof is by pseudo-languages, one per paradigm, weighed on evidence. Sources: [S1]…[S20].

## 1. Goals and non-goals

Goals: any number of interface languages without touching code; plurals, select and gender by CLDR rules; a language
chosen by the person, the system's list by default, a fallback chain; Go-side texts (startup notifications, the native
close dialog, errors, `.desktop`, AppStream) from the same catalogs; extensions bring their own catalogs; an interface
that survives longer, shorter, taller, unspaced and right-to-left text, proved by machine on every surface; a
translators' workflow with context and screenshots. Non-goals: shipping a third language (owner, §9); an RTL layout
shipped now (§5); translating documents' content; locale-specific keyboard shortcuts (spec §8.2 keeps its rules).

State measured on `main` (238053d): 905 keys per language, 70 `.one`/`.other` pairs, 195 messages with `{name}`
placeholders, parity clean; `tn()` drops CLDR `few`/`many`/`two`/`zero`; the language is `navigator.language` (en or
fr, else fr), while Go guesses its own from `LC_ALL`/`LC_MESSAGES`/`LANG` (`cmd/inkwell/startup.go:282`, ignores
`LANGUAGE` [S12]): two detections that can disagree. Hard-coded `"fr"` in `Intl` constructors (`editor/stats/stats.ts:63`,
`editor/csv/view.ts:24`); module-level formatters bound at load (`history/when.ts`); `fold.ts` strips every
combining mark (wrong for Devanagari, Thai, Arabic, where marks are vowels) and lower-cases without a locale (Turkish
İ/ı); the native close dialog (`cmd/inkwell/close_view.go`), the session-logout reason and the sidecar errors are
French only; `<html lang="fr">` is fixed; both catalogs (~97 kB) are in the start bundle.

## 2. Decisions, each against an alternative

| # | Decision | Rejected, and why |
|---|---|---|
| D1 | **Unicode MessageFormat 2** syntax in the catalogs: stable since CLDR 47 (March 2025) [S1]; `.match` on `:number` (plural, ordinal) and `:string` (select, gender); `*` catch-all mandatory | ICU MF1/FormatJS [S3]: legacy syntax MF2 replaces, nested plurals; Fluent [S4]: strong asymmetric model, but a smaller toolchain and Weblate support marked « in development » [S15]; i18next: suffix keys (`_one`) and a runtime of 200–400 kB in the Paraglide benchmark [S5] |
| D2 | **Compile at build to the MF2 data model** (JSON, part of the spec [S1]) with `messageformat@4` [S2] as a *build/test-only* dependency; one tiny interpreter at run time (text, variables, `:number`, `:string`, `.match` via `Intl.PluralRules`); typed keys **and arguments** generated as `messages.d.ts` | **Paraglide JS 2** [S5][S6]: compile-time and typed too, but its locale strategies target URLs and SSR, it cannot compile a catalog that arrives at run time (extensions, §2 D7), and its MF2 status is not documented; `Intl.MessageFormat`: TC39 stage 1 [S7], not usable; runtime `messageformat@4`: a parser in the start path for nothing |
| D3 | **Go negotiates once**: the OS's ordered list (Linux `LANGUAGE`, then `LC_ALL`, `LC_MESSAGES`, `LANG`, `C`/`POSIX` = none [S12]; macOS `CFLocaleCopyPreferredLanguages`; Windows `GetUserPreferredUILanguages`), matched by `golang.org/x/text/language.Matcher` (already in `go.mod`, v0.44.0) [S11]; the result goes to the webview | `navigator.languages` in WebKitGTK/WebView2: engine-dependent and not the list the OS gives; two negotiators (today) disagree; Wails v3 has no locale API [S13] |
| D4 | **Chain**: chosen or negotiated locale → its CLDR parents (`fr-CA` → `fr`) → `en` → `fr` (source). No match → **en** (a Spanish system reads English more often than French). A locale **ships only when complete** (lint), so per-message fallback exists only for extensions | French as the terminal default: right for the owner, wrong for most systems that match nothing; shipping partial catalogs: mixed-language screens and wrong `lang` for screen readers |
| D5 | **Go texts**: errors that reach the webview carry a code and arguments, the webview writes the text; texts shown with no webview (startup notifications, native close dialog, session logout) come from catalog keys `native.*` (variables only, no `.match`; lint), embedded and read by a 30-line Go formatter; `.desktop` and AppStream generated from `desktop.*` keys at build (test: generated = committed) | `golang.org/x/text/message` + `gotext` [S11]: a second catalog format and extraction step for about 15 messages |
| D6 | **Start cost**: only the active catalog is in the start chunk; the others are lazy `import()`; the palette's « other language » folding (`textIn`) loads it on first palette open or at idle. Formatters cached per locale (`intl.ts`), never bound at module load | Both catalogs eager (today): +46 kB parsed at every start for a fallback that a complete catalog never uses |
| D7 | **Extensions** (ADR 0027): manifest `label` fields hold `%key%`; the extension ships `l10n/<locale>.json` in the D2 data model, namespaced by its id (it cannot override an app key: no « Partager » spoofing); its chain ends at its own default locale; labels stay unique per locale with the app's (EX0c3 check extended); elements carry `lang` when the resolved locale differs | VS Code's `package.nls.json` + `bundle.l10n.<locale>.json` [S14] is the model for the split (manifest vs code strings); we keep one format instead of two |
| D8 | **Translators**: source `fr`, flat JSON of MF2 strings, a sidecar `context.json` (description, max length, screenshot path) per key; screenshots produced by the UX1-0 harness from `data-i18n-key` marks (dev builds only); machine drafts by `scripts/llm.sh` (ADR 0013) marked `draft` and never shipped unreviewed; a hosted platform later (Weblate [S15] or Pontoon) | XLIFF/PO as the source: lossy for MF2 `.match`; a platform now: no translator community yet, and hosting is a public act (§9) |
| D9 | **Language setting**: Preferences → « Langue de l'interface », an Adwaita combo row (spec §4), first item « Langue du système (Français) », then each shipped language by its own name (`Intl.DisplayNames` in that language [S9]); per device, never synced; **live switch** (reactive locale; native menus rebuilt by Go), no restart | Restart to apply: simpler, but loses the view state and is a dead end for the live preview of the choice |

## 3. Interface rules IL-1…IL-12 (cited by UX1; each proved at the named UX1 step)

| Rule | Text | Proof, step |
|---|---|---|
| IL-1 | No fixed `width`/`height` in `px` on a text-bearing element; `min-*` allowed; heights from line height | source lint in EL-7 (UX1-C), EL-4 under PL-1 (UX1-D) |
| IL-2 | Never truncated: buttons, menu items, titles, dialog and banner text, toasts, errors, setting labels (they wrap or the layout grows). Ellipsis **plus tooltip and full accessible name** only for user content on one line: file, project, person names, tab titles, status items | EL « clipped » check (UX1-0), component states (UX1-C), every surface (UX1-D) |
| IL-3 | Budget by length, IBM's table via W3C [S16]: ≤ 10 chars ×2, 11–20 ×1.8, 21–30 ×1.6, 31–70 ×1.4, > 70 ×1.3; German and Finnish compounds cannot break, so `overflow-wrap: anywhere` only in user content, `hyphens: auto` with `lang` in prose | PL-1 at 640 px and default width, light and dark (UX1-D) |
| IL-4 | Contraction (CJK and terse languages, about half the length): targets keep their minimum size, button rows keep equal widths | PL-2, EL-4 widths and targets (UX1-D) |
| IL-5 | Tall and stacked scripts: line height unitless (≥ 1.45, tokens), no `overflow: hidden` that clips ascenders or descenders; `lang` on `<html>` so Han unification picks Japanese or Chinese glyphs [S18] | PL-1 stacked marks, real-script fillers RS-th/RS-hi (UX1-C, UX1-D) |
| IL-6 | Fonts: `--font-ui` (Adwaita Sans, Inter-derived [S17]) covers Latin, Greek, Cyrillic; other scripts fall back per `:lang()` to the system's Noto (CJK, Arabic, Devanagari, Thai), then `system-ui`; no bundled CJK font; code keeps `--font-mono`, prose `--font-ui`/`--font-serif` | a test checks each shipped locale's CLDR exemplar characters against the font coverage (no `.notdef`) (UX1-C) |
| IL-7 | Text is never measured as characters × width; counts and caret move by grapheme (`Intl.Segmenter`) [S9] | unit vectors (emoji ZWJ, Devanagari conjuncts), editor e2e (I18N1-c, UX1-D editor) |
| IL-8 | Word boundaries by `Intl.Segmenter` of the text's language: the palette's words (fold.ts today splits on French separators), word counts (OBS1, stats), the editor's word motion | real-text vectors ja, zh, th (I18N1-c) |
| IL-9 | Matching folds by script: marks removed only on Latin, Greek and Cyrillic bases; lower case with the UI locale (`tr`: İ/ı); sorting with `Intl.Collator` of the UI locale (lists) or of the content (grid) | palette vectors tr, hi, th, ar (I18N1-c) |
| IL-10 | No key action while composing (`isComposing` or `keyCode` 229) in any handler, through the shared helper of `extensions/keys.ts`; Enter ends a composition, never submits | lint « keydown outside the helper » (EL-7, UX1-C), composition e2e through CDP `Input.imeSetComposition` (UX1-D) |
| IL-11 | Every user value placed in a message (names, file names, paths, numbers next to RTL text) is bidi-isolated: MF2's default bidi strategy [S1] in the interpreter (FSI…PDI in strings, `<bdi>`/`dir="auto"` in the DOM) [S19] — needed now, a French UI can show an Arabic name | interpreter vectors; PL-3 report (UX1-D) |
| IL-12 | `<html lang dir>` follows the UI locale (`Intl.Locale` text info); an extension label in another locale carries its `lang`; no literal text, no concatenation of messages, no fixed locale in an `Intl` constructor | axe `html-has-lang`/`valid-lang` (UF-1), source lints (I18N1-a) |

## 4. Proof strategy: pseudo-locales where they are faithful, real-script samples where they are not

Pseudo-locales find layout and wiring defects in every message without translators, deterministically (Microsoft's
`qps-ploc`, `qps-plocm`, `qps-ploca` [S20]; Android's `en-XA`, `ar-XB` [S10]). They **cannot** imitate behaviour that
lives in the script itself: CJK line breaking (UAX #14 classes, kinsoku), Thai segmentation (dictionary-based, no
spaces), Arabic cursive joining (shaping changes widths), Indic conjuncts and vowel reordering, real font fallback.
Latin text without spaces gives `Intl.Segmenter` nothing to find, and full-width Latin does not break or shape like
CJK. So the set is four generated pseudo-locales plus checked-in real-script samples, all deterministic:

| Id | Built from the source catalog | Defects it must reveal |
|---|---|---|
| **PL-1** `en-XA` long | accents above and below (stacked), IL-3 expansion with a fixed filler, markers `⟦…⟧`, plural messages expanded to **Arabic's six categories** (`zero` `one` `two` `few` `many` `other`), each variant tagged with its category | fixed widths, truncation without ellipsis (missing `⟧`), clipping, concatenation (`⟧⟦` in one element), **any visible text without a marker = hard-coded**, hand-made plurals, the palette's folding (typing plain words finds accented labels) |
| **PL-2** `en-XS` short | each word cut to about half, at least one letter | shrunk targets, unequal button widths, layouts that need long labels |
| **PL-3** `ar-XB` mirrored | `dir="rtl"`, text reversed as Android does, placeholders kept isolated | physical CSS properties, unmirrored directional icons, names, paths and numbers not isolated |
| **PL-4** plural vectors (not a display locale) | CLDR 48 `plurals.json` samples for ar, pl, ru, fr (`many` for 10⁶), en, ja | the interpreter selects by `Intl.PluralRules`; every shipped locale's plural message lists exactly its CLDR categories (lint) |
| **RS-ja, RS-zh, RS-th, RS-ar, RS-hi, RS-vi, RS-tr** real-script samples | a fixed corpus (filler words for the shell's messages by length band; sentences with known word and grapheme boundaries; names and file names) | font fallback and line height in the chrome, CJK and Thai breaking, Arabic shaping, conjunct graphemes, Turkish case, stacked Vietnamese |

Rejected: a « no spaces » Latin pseudo-locale and a full-width one (they test nothing real, see above); a separate
« tall marks » locale (PL-1 and RS-th, RS-vi cover it); one locale per plural paradigm (CLDR's mapping is the engine's
job, PL-4 proves our use of it); layout tests on machine translations (non-deterministic, tied to wording). Each
**generator** is a pure function over the MF2 data model, touching text parts only, with property tests (fast-check):
placeholders and variant keys kept in order, output valid MF2, length within its band, same input → same output.
**Where they run**: the locale becomes a factor of UX1-0's pairwise state generator (`scripts/ux_states.py`), with
PL-1 on every state; EL-4 and three new element checks — **clipped** (scroll size > client size on a text element
without the IL-2 ellipsis role), **overlap** (sibling boxes intersect), **overflow** (beyond container or viewport at
640 px) — and **unmarked** (PL-1 only) run on every surface, light and dark. Blocking: PL-1, PL-2, RS-* for clipping
and fonts after UX1-C; PL-3 reports until RTL ships. A shipped real language then needs one machine smoke run of the
same checks (minutes) and a native review of wording only. Also proved: the **migration equivalence** (§6), the
lints (missing, unused, placeholder parity, valid MF2, categories, no literal text in `.svelte` text and
`aria-label`/`title`/`placeholder`, no concatenation, no fixed-locale `Intl`), interpreter output = `messageformat@4`
output for every message × sample arguments (differential, test-only), and PERF-START paired, with the start chunk
holding exactly one catalog.

## 5. Right-to-left: prepared now, shipped with the first RTL language

Now (cheap, and needed even in French): bidi isolation (IL-11), `dir` from the locale (IL-12), logical CSS properties
enforced by a lint, PL-3 as a report on each surface UX1-D touches. Later, block **I18N-RTL** when the owner picks an
RTL language: directional icons mirrored (a `mirror` flag per icon in the registry), PL-3 blocking, RS-ar on every
surface. Reason: mirroring proof on surfaces that UX1-D is about to redesign would be paid twice; isolation and logical
properties are not.

## 6. Migration of the 905 keys (mechanical, provable)

A script rewrites `{name}` → `{$name}`, escapes literal `{` `}` `\`, merges each `.one`/`.other` pair into one
`.match {$count :number}` message (`one` and `*`), and rewrites `tn(base, n, vars)` calls to `t(base, {count: n, …})`
(41 call sites). Proof before the old code is deleted: for every key, both languages and the arguments
{0, 1, 2, 5, 21, 1.5, 10⁶} plus each message's placeholder names, old `t()`/`tn()` output = new output, byte for byte
(French `many` folds into `*` exactly as `tn()` did). Hard-coded locales and load-time formatters move to `intl.ts`.

## 7. Split and order

- **I18N1-a** catalog core: D1, D2, D6, the migration, lints, PL-4, interpreter and its differential test. No visible change.
- **I18N1-b** the language: D3, D4, D5, D9, `<html lang dir>`, Go codes and `native.*`, `.desktop`/AppStream generation, live switch e2e.
- **I18N1-c** interface robustness: generators PL-1…PL-3, RS corpus, IL-7…IL-11 fixes (segmenter, fold, collator,
  IME helper lint), the locale factor and the four checks given to UX1-0's harness.
- **I18N1-d** extension catalogs (D7, ADR 0027 amended), with the first block that loads extension labels from a
  project; complete rigour then (bounded decoder, fuzzed).

Order: IV1 → I18N1-a → I18N1-b → UX1-0 (if its gate is not yet frozen, I18N1-c's checks enter it; otherwise I18N1-c
follows it) → UX1-A → UX1-B (writes every text in MF2, against IL-1…IL-5) → UX1-C (IL-5, IL-6, IL-10 lints) → UX1-D
(every IL proved per surface) → I18N-RTL when asked.

## 8. Decided here (logged in `docs/autonomous-decisions.md`)

D1–D9, IL-1…IL-12, the proof set of §4, RTL later (§5), English as the no-match default (D4), the split and order.
