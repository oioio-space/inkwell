# I18N1 — several interface languages (W88)

Rigour: **standard** (I18N1-a…c, e); **complete** for I18N1-d only if extension catalogs arrive inside a synced
project (peer bytes). Owner request W88 (2026-11-25), with two addenda the same day: the interface side (characters,
word length) is first-class, and the proof is by pseudo-languages weighed on evidence; owner's decisions of
2026-11-25 (`docs/design/decisions-utilisatrice.md`) in §9–§10. Revised 2026-11-28 after a critical review (code
re-measured on `88563a5`, sources re-checked). Sources: [S1]…[S29].

## 1. Goals, non-goals, measured state

Goals: any number of interface languages without touching code; plurals, select and gender by CLDR rules; a language
chosen by the person, the system's list by default, a fallback chain; Go-side texts (startup notifications, the native
close dialog, errors, `.desktop`, AppStream) from the same catalogs; extensions bring their own catalogs; an interface
that survives longer, shorter, taller, unspaced and right-to-left text, proved by machine on every surface; the
fourteen languages of §9, machine-translated under the guards of §10. Non-goals: translating documents' content;
spell checking (none today; WebKitGTK's per-language checker is an editor function → EF1); locale-specific shortcuts.

State on `88563a5`: 905 keys per language; **34** `.one`/`.other` pairs, plus `kind.other` and
`present.pilot.other`, which are *not* plurals; 195 messages with `{name}`; `tn()` (24 call sites) drops CLDR
`few`/`many`/`two`/`zero`; a third plural path, `ui/shell/count.ts`, appends « s » in English and calls `stats.ts`'s
French-only `formatCount`. The webview reads `navigator.language` (en, else fr), Go its own `LC_ALL`/`LC_MESSAGES`/
`LANG` (`cmd/inkwell/startup.go:283`, no `LANGUAGE` [S12]): two detections that can disagree. Hard-coded `"fr"`:
`stats.ts:55,68-69`, `stats/words.ts:27,156`, `csv/view.ts:24`; closed `"fr" | "en"` types with their own labels in
`extensions/keys.ts:205` (« Maj ») and `ui/command/entries.ts:11`; load-time formatters in `history/when.ts` and
`i18n/index.ts`. `ui/command/fold.ts` drops every `\p{M}` after NFKD (Indic and Arabic vowel signs, Japanese voicing
marks: が folds to か) and never folds `I`/`ı` together. The native close dialog, the session-logout reason and the
sidecar errors are French only; `<html lang="fr">` is fixed; both catalogs (~97 kB) are in the start bundle.

## 2. Decisions, each against an alternative

| # | Decision | Rejected, and why |
|---|---|---|
| D1 | **Unicode MessageFormat 2** syntax: stable since CLDR 47 [S1]; `.match` on `:number` (plural, ordinal) and `:string` (select, gender); `*` catch-all mandatory | ICU MF1/FormatJS [S3]: the syntax MF2 replaces, nested plurals; Fluent [S4]: strong model, smaller toolchain, no CLDR-standard data model; i18next: suffix keys (`_one`), its MF2 bridge `i18next-mf2` is young (47 weekly downloads, Oct 2026 [S22]); `Intl.MessageFormat`: still TC39 stage 1 [S7][S22] |
| D2 | **Parse at build, format with the reference library**: catalogs compiled to the MF2 data model (JSON, part of the spec [S1]); at run time `messageformat@4` (`new MessageFormat(locale, dataModel, {bidiIsolation})` accepts the data model [S29]; 25.1 kB min, 8.2 kB gzip [S21]) builds a key's formatter on first use and caches it; typed keys **and arguments** generated as `messages.d.ts` | **A home-made interpreter** (previous draft): it would own MF2 conformance (bidi strategy, fallback, `:number` options, escapes) to save about 8 kB; only if PERF-START shows the library's cost, and then with a differential test against it. **Paraglide JS 2** [S5][S6]: compile-time and typed, client strategies exist, but it compiles messages to functions and cannot take a catalog that arrives at run time (extensions, D7); runtime parsing: a parser in the start path |
| D3 | **Go negotiates once**: the OS's ordered list (Linux `LANGUAGE` unless the locale is `C`/`POSIX`, then `LC_ALL`, `LC_MESSAGES`, `LANG` [S12]; macOS `CFLocaleCopyPreferredLanguages`; Windows `GetUserPreferredUILanguages`), each tag matched in order by `x/text/language.Matcher` (in `go.mod`, v0.44.0) [S11], accepted at confidence `High` or better, else the next tag; the result goes to the webview. Vectors: `zh-TW`→`en`, `pt-PT`→`pt-BR`, `es-MX`→`es`, `de-CH`→`de`, `C`→`en` | `navigator.languages` in WebKitGTK/WebView2: engine-dependent, not the OS list; two negotiators (today) disagree; Wails v3 has no locale API [S13]; trusting the Matcher's default tag on `No` confidence (silently the first supported tag) |
| D4 | **Chain**: chosen or negotiated locale → its CLDR parents (`fr-CA` → `fr`; `zh-Hant`'s parent is root, so Simplified is never shown to a Traditional reader) → `en`. No match → **en**. A locale **ships only when complete** (lint), so per-message fallback exists only for extensions | French as the terminal default: wrong for most systems that match nothing; partial catalogs: mixed screens, wrong `lang` for screen readers |
| D5 | **Go texts**: errors that reach the webview carry a code and arguments, the webview writes the text; the codes are one enum generated from `error.*` keys for Go and TypeScript (lint: every code has a key in every locale); texts shown with no webview come from `native.*` keys (variables only, no `.match`; lint), embedded and read by a 30-line Go formatter; `.desktop` and AppStream generated from `desktop.*` keys at build (test: generated = committed) | `x/text/message` + `gotext` [S11]: a second catalog format and extraction for about 15 messages; free-text Go errors: untranslatable |
| D6 | **Start cost**: only the active catalog in the start chunk, the others lazy `import()`; the palette's « other language » folding (`textIn`) loads on first palette open or at idle; formatters cached per locale in `intl.ts`, never bound at module load | Both catalogs eager (today): +46 kB parsed at every start for a fallback a complete catalog never uses |
| D7 | **Extensions** (ADR 0027): manifest `label` fields hold `%key%`; the extension ships `l10n/<locale>.json` in the D2 data model, namespaced by its id (it cannot override an app key: no « Partager » spoofing); its chain ends at its own default locale; labels unique per locale with the app's (EX0c3 check extended); elements carry `lang` when the resolved locale differs | VS Code's `package.nls.json` + `bundle.l10n.<locale>.json` [S14] is the model for the split; one format instead of two |
| D8 | **Translation sources**: `fr` source, `en` pivot, flat JSON of MF2 strings; a sidecar `context.json` per key **generated** from its call sites (component, element role, IL-3 budget, screenshot from the UX1-0 harness's `data-i18n-key` marks, dev builds only), plus a hand-written description required (lint) for labels of one or two words; no translation platform (owner, 2026-11-25); machine translation by §10 | XLIFF/PO as the source: lossy for `.match`; Weblate's MF2 support is not documented [S15] and the owner declined a platform; 905 hand-written descriptions: cost without gain where the call site says it |
| D9 | **Language setting**: Preferences → « Langue de l'interface », an Adwaita combo row (spec §4), first « Langue du système (Français) », then each shipped language by its own name (`Intl.DisplayNames` in that language [S9]) followed, for a machine-translated catalog, by « traduction automatique » in the current interface language; per device, never synced; **live switch** (reactive locale, formatters and segmenters rebuilt, native menus rebuilt by Go) | Restart to apply: loses the view state |
| D10 | **Bidi in the DOM**: messages render through `formatToParts`, each placeholder in a `<bdi>`; FSI…PDI isolates only in strings that leave the DOM's structure (`title`, `aria-label`, notifications); one e2e text helper strips isolates | Isolates in every string: they reach clipboard copies and break text matching in tests; no isolation: an Arabic name reorders a French sentence |

## 3. Interface rules IL-1…IL-14 (cited by UX1; each proved at the named step)

| Rule | Text | Proof, step |
|---|---|---|
| IL-1 | No fixed `width`/`height` in `px` on a text-bearing element; `min-*` allowed; heights from line height | source lint in EL-7 (UX1-C), EL-4 under PL-1 (UX1-D) |
| IL-2 | Never truncated: buttons, menu items, titles, dialog and banner text, toasts, errors, setting labels (they wrap or the layout grows). Ellipsis **plus tooltip and full accessible name** only for one-line user content: file, project, person names, tab titles, status items | EL « clipped » check (UX1-0), component states (UX1-C), every surface (UX1-D) |
| IL-3 | Budget by length, IBM's table via W3C [S16]: ≤ 10 chars ×2, 11–20 ×1.8, 21–30 ×1.6, 31–70 ×1.4, > 70 ×1.3; compounds that cannot break (German, Finnish): `overflow-wrap: anywhere` only in user content, `hyphens: auto` with `lang` in prose | PL-1 at 640 px and default width, light and dark (UX1-D); §10 length check |
| IL-4 | Contraction (CJK, about half the length): targets keep their minimum size, button rows keep equal widths | PL-2, EL-4 widths and targets (UX1-D) |
| IL-5 | Tall and stacked scripts: unitless line height (≥ 1.45, tokens), no `overflow: hidden` that clips ascenders or descenders; `lang` on `<html>` so Han unification picks Japanese or Chinese glyphs [S18] | PL-1 stacked marks, RS-th/RS-hi (UX1-C, UX1-D) |
| IL-6 | Fonts: `--font-ui` (Adwaita Sans, Inter-based [S17]: Latin, Greek, Cyrillic) then, per `:lang()`, the system's Noto (CJK, Arabic, Devanagari), then `system-ui`; no bundled CJK font; the deb and rpm packages *recommend* the Noto core and CJK font packages | per shipped locale, the rendered font of its CLDR exemplar characters through CDP `CSS.getPlatformFontsForNode` is a named family, never a last resort; CI images carry the fonts (UX1-C) |
| IL-7 | Text is never measured as characters × width; counts and caret move by grapheme (`Intl.Segmenter`) [S9] | unit vectors (emoji ZWJ, Devanagari conjuncts), editor e2e (I18N1-c) |
| IL-8 | Word boundaries by `Intl.Segmenter`: the palette's words (fold.ts splits on French separators), word counts (OBS1, stats), the editor's word motion | real-text vectors ja, zh, th (I18N1-c) |
| IL-9 | Matching folds by script: marks removed only on Latin, Greek and Cyrillic bases (Japanese voicing marks and Indic vowel signs kept); `I`, `İ`, `ı`, `i` fold to `i` whatever the locale (a search equivalence; `tr` lower-casing would split `I` from `i`); sorting with `Intl.Collator` of the UI locale (lists) or of the content (grid) | palette vectors tr, hi, ja, ar (I18N1-c) |
| IL-10 | No key action while composing (`isComposing` or `keyCode` 229), through the shared helper of `extensions/keys.ts`; Enter ends a composition, never submits | lint « keydown outside the helper » (UX1-C), composition e2e through CDP `Input.imeSetComposition` (UX1-D) |
| IL-11 | Every user value placed in a message (names, file names, paths, numbers next to RTL text) is bidi-isolated (D10, MF2's default strategy [S1][S19]) — needed now, a French UI can show an Arabic name | formatter vectors; PL-3 (UX1-D) |
| IL-12 | `<html lang dir>` follows the UI locale (`Intl.Locale` text info); an extension label in another locale carries its `lang`; no literal text, no concatenation, no fixed locale in an `Intl` constructor, no closed language type outside `i18n/` | axe `html-has-lang`/`valid-lang` (UF-1), source lints (I18N1-a) |
| IL-13 | **Content follows the content's language, chrome follows the UI's**: word counts, segmentation, the CSV grid's sort, quotes and dates *inside* a document use the document's language (Typst `text(lang:)`, Markdown `lang`), else the UI's; the editor's text direction is per line (`dir="auto"`); a new document's template takes the UI language once, at creation | vectors: a German document in a French UI counts German words; an Arabic line in a French document is right-to-left (I18N1-c) |
| IL-14 | Shortcuts work on non-Latin layouts: a chord resolves by the key's base under a modifier (`Ctrl+и` is `Ctrl+b`, `eventChord` today); key names shown (« Maj », « Shift ») come from `keys.*` catalog keys | `eventChord` vectors for ru, ar, hi, ja layouts; lint IL-12 on `keys.ts` (I18N1-c) |

## 4. Proof strategy: pseudo-locales where they are faithful, real-script samples where they are not

Pseudo-locales find layout and wiring defects in every message without translators (Microsoft's `qps-ploc*` [S20],
Android's `en-XA`, `ar-XB` [S10]), but **cannot** imitate what lives in the script: CJK breaking (UAX #14, kinsoku),
Thai segmentation, Arabic joining, Indic conjuncts, real font fallback. So four generated pseudo-locales plus
checked-in real-script samples, all deterministic:

| Id | Built from the source catalog | Defects it must reveal |
|---|---|---|
| **PL-1** `en-XA` long | stacked accents, IL-3 expansion with a fixed filler, markers `⟦…⟧`; plural messages expanded to Arabic's six categories and **selected with `ar` plural rules**, so every category is reachable, each variant tagged | fixed widths, truncation (missing `⟧`), clipping, concatenation (`⟧⟦` in one element), **visible text without a marker = hard-coded**, hand-made plurals, the palette's folding |
| **PL-2** `en-XS` short | each word cut to about half, at least one letter | shrunk targets, unequal button widths |
| **PL-3** `ar-XB` mirrored | `dir="rtl"`, text reversed as Android does, placeholders kept isolated | physical CSS properties, unmirrored directional icons, names, paths and numbers not isolated |
| **PL-4** plural vectors (no display) | CLDR 48 `plurals.json` samples for ar, pl, ru, fr (`many` for 10⁶), en, ja | each shipped locale's plural message lists exactly its CLDR categories (lint) |
| **RS-ja, -zh, -ko, -th, -ar, -hi, -tr** real scripts | a fixed corpus: filler words by length band for the shell's messages; sentences with known word and grapheme boundaries; names and file names | font fallback and line height, CJK and Thai breaking, Arabic shaping, conjuncts, Turkish case |

Rejected: a « no spaces » Latin locale and a full-width one (Latin without spaces gives `Intl.Segmenter` nothing to
find; full-width Latin neither breaks nor shapes like CJK); a separate « tall marks » locale (PL-1 and RS-th cover
it); one locale per plural paradigm (CLDR's mapping is the library's job, PL-4 proves our use); layout tests on
machine translations (non-deterministic). Each **generator** is a pure function over the data model, touching text
parts only, with property tests (fast-check): placeholders and variant keys kept, valid MF2, length within its band,
deterministic. **Where they run**: the locale is a factor of UX1-0's pairwise state generator (`scripts/ux_states.py`),
PL-1 on every state; EL-4 and three element checks — **clipped** (scroll size > client size without the IL-2 ellipsis
role), **overlap**, **overflow** (at 640 px) — and **unmarked** (PL-1) on every surface, light and dark. Blocking:
PL-1, PL-2, RS-* after UX1-C; **PL-3 per surface from UX1-D** (§5). A shipped language then needs one machine smoke
of the same checks on its real catalog (§10). Also proved: §6, the lints (missing, unused, placeholder parity, valid
MF2, categories, IL-12), and PERF-START paired, the start chunk holding exactly one catalog.

## 5. Right-to-left: in R1, because Arabic ships

Arabic is in §9, so mirroring is an R1 requirement, no longer « when asked ». Now (I18N1-a…c): isolation (IL-11,
D10), `dir` from the locale (IL-12), logical CSS properties by lint, per-line direction in the editor (IL-13). In
**UX1-D**: PL-3 is blocking on each surface it redesigns, so mirroring is proved once, on the final surfaces (the
earlier reason for deferring still holds: never pay it twice). **I18N-RTL** moves into the R1 path, after UX1-D and
before the string freeze: a `mirror` flag per icon in the registry, RS-ar on every surface, the native menus and
dialogs in RTL, the Arabic catalog through §10. `PROGRESS.md` (point 3, I18N1 line) is to be updated by the
integrator: I18N-RTL and the string freeze (§7) as R1 blocks.

## 6. Migration of the 905 keys (mechanical, provable)

A script rewrites `{name}` → `{$name}`, escapes literal `{` `}` `\`, merges each of the 34 `.one`/`.other` **pairs**
(never a lone `.other`: `kind.other` and `present.pilot.other` stay plain keys) into one `.match {$count :number}`
message (`one` and `*`), rewrites the 24 `tn(base, n, vars)` calls to `t(base, {count: n, …})`, and replaces
`count.ts`'s and `formatCount`'s hand-made plurals by `count.*` messages. Proof before the old code is deleted, run
with `bidiIsolation: "none"`: for every key, both languages and the arguments {0, 1, 2, 5, 21, 1.5, 10⁶} plus each
message's placeholder names, old output = new output, byte for byte (French `many` folds into `*` as `tn()` did);
`count()` compared the same way. A missing argument is a type error, not a compared case. Isolation (D10) is then switched on as its own step, with its
own vectors. Hard-coded locales and load-time formatters move to `intl.ts`.

## 7. Split and order

- **I18N1-a** catalog core: D1, D2, D6, D10, the migration, lints, PL-4. No visible change.
- **I18N1-b** the language: D3, D4, D5, D9, `<html lang dir>`, Go codes and `native.*`, `.desktop`/AppStream, live
  switch e2e; the §10 tooling and its 60-key pilot (light tier, no catalog shipped).
- **I18N1-c** robustness: PL-1…PL-3, RS corpus, IL-7…IL-9, IL-13, IL-14 fixes, the IME helper lint, the locale factor
  and the four checks given to UX1-0's harness.
- **I18N1-d** extension catalogs (D7, ADR 0027 amended), with the first block that loads extension labels from a
  project; complete rigour then (bounded decoder, fuzzed).
- **I18N1-e** the languages of §9: string freeze, the §10 run on the frozen catalog, the « Signaler une traduction »
  dialog, the machine smoke per language.

Order: IV1 → I18N1-a → I18N1-b → UX1-0 (I18N1-c's checks enter its gate if not yet frozen, else I18N1-c follows) →
UX1-A → UX1-B (every text in MF2, against IL-1…IL-5) → UX1-C → UX1-D (every IL per surface, PL-3 blocking) →
**I18N-RTL** → **string freeze** → I18N1-e → R1. **String freeze**: from the freeze to the release tag, no key added or
reworded except a defect fix, which re-runs §10 for that key (lint against `i18n/freeze.json`, the frozen catalog's
hash); translations run once per release, on the frozen text.

## 9. Languages shipped (owner: « la majorité des gens », 2026-11-25)

Criteria, each measured: total speakers L1+L2 (Ethnologue 2026 [S23]), internet users by language (IWS [S24]),
desktop UI language (Steam survey, Oct 2026, the only large desktop sample [S25]), the Linux desktop's own coverage
(GNOME 49 UI statistics [S26]: a locale the desktop does not translate is rarely set), and maintainability (≤ 14).

| Ship (14) | Why |
|---|---|
| en, fr | existing; fr source, en pivot and default |
| zh-Hans, es, pt-BR, ru, de, ja | the six largest after English by desktop share (21.98, 5.72, 4.46 (+pt-PT 0.36), 10.14, 2.89, 2.47 %) and all in IWS's top 10 |
| ar | 5th by speakers (335 M MSA), 4th by internet users (5.2 %); Steam ≈ 0 % and GNOME 47 % show Arabic desktops often run in English or French, but the reach and RTL in the architecture outweigh it (§5) |
| hi | 3rd by speakers (611 M), GNOME 91 % |
| id | 9th by speakers (255 M), 5th online (4.3 %), GNOME 99 % |
| ko, tr, it | desktop shares 1.36, 1.35, 0.64 %, GNOME 85, 100, 96 % |

Coverage: the ten largest internet languages (**76.8 %** of internet users, IWS) are all in, plus ko, tr, it, hi; the
set is **≈ 93 %** of the Steam desktop sample's UI languages. Not now, next by the same measures: bn (274 M speakers,
GNOME 35 %), ur (GNOME 0 %), vi (GNOME 68 %), pl (Steam 1.73 %), zh-Hant (1.30 %), uk, th; each is one §10 run plus
its RS sample. `pt-PT` reads pt-BR and `es-419` reads es (D4); `zh-Hant` reads English until it ships.

## 10. Machine translation with three guards (owner, 2026-11-25), no platform

1. **Translate** (`scripts/llm.sh translate <locale>`, writing route: paid OpenRouter, ZDR, no `:free`/`:batch`, ADR
   0013): batches of about 100 keys with `fr`, `en`, `context.json`, `docs/glossary.md` and a per-locale term list
   (`i18n/terms/<locale>.json`, kept stable across releases); output MF2 strings.
2. **Machine checks** (no model, blocking): valid MF2; same variables; `.match` with exactly the locale's CLDR
   categories plus `*`; no markup or isolate characters added; length ≤ the IL-3 budget of the source (above it: the
   key is flagged, not cut); script check (letters outside the locale's CLDR exemplars and the source's names
   flagged); term list respected; then the §4 machine smoke on the real catalog (clipped, overflow, fonts).
3. **Second model, another family** (guard 1): per key, `ok` or an issue with a wording; issues go back once to the
   translator; a key still disputed is flagged. A locale with more than 2 % flagged keys does not ship that release
   (it keeps its previous catalog, or waits). Translator and reviewer are fixed per locale by the I18N1-b pilot (60
   keys, scored by the reviewer and back-translation); defaults: `google/gemini-3.1-pro-preview` translates (Gemini
   led the LLMs at WMT25 [S28]), `anthropic/claude-sonnet-5.5` reviews; `mistral-large-4-0` (ADR 0013) for European
   locales if the pilot shows parity.
4. **Mark** (guard 2): the catalog's metadata says `machine` (models, date, frozen hash); D9 shows « traduction
   automatique ». A locale becomes `reviewed` only when a fluent person has read it all.
5. **Report** (guard 3): « Signaler une traduction », in the language row and the palette: pick the wording through the
   palette's search over the active catalog, write a better one; the report (locale, key, current text, suggestion,
   version) is copied or saved as a file, to send through the contact in « À propos ». The application sends nothing.

**Cost** (prices of [S27], 2026-11-28; catalog 52 kB ≈ 14 k tokens, inputs ≈ 85 k tokens per locale with pivot,
context and batches, outputs 14 k tokens in Latin scripts to 35 k in Arabic, Devanagari or CJK): translation
$0.34–0.59, review $0.27–0.31, revision ≈ $0.05, so **≈ $0.65–0.95 per locale** for a full catalog; the twelve
locales ≈ $9, **≈ $14 with the pilot and one retry**; per release, only changed keys (≤ 10 %, context resent):
**≈ $0.15 per locale, ≈ $2 per release**. The script records the real cost per run (`/api/v1/credits` before and after).

**For the owner** (closed list, money): this spending is beyond the review budgets already granted (method v2);
I18N1-e waits for her agreement on about $14 once and $2 per release.
