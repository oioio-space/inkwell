**R-E2E2-1 → PR1, WC1.** A page cannot count on its last word in WebKit (as R-E2E1-1 for saving). PR1's frozen e2e

## Residuals

- **R-E2E1-1 → WC1 (window close), data loss.** A page cannot be trusted to save in its last moments:
  (1) on a reload WebKit does not deliver what the page sends from `pagehide`; (2) the desktop window is destroyed
  with `gtk_window_destroy` (Wails v3 `linux_cgo.go`), never `webkit_web_view_try_close`, so the page gets no
  `pagehide` at all; (3) `drainOnClose` is an `OnWindowEvent` listener, which Wails runs in a goroutine beside its
  own closing listener: it does not hold the window, unlike rule D-DRAIN at close of `OISingleInstance.tla`;
  (4) the store server drops a request read on a connection already replaced by a reload
  (`storestream.go`, « replaced »). Design to specify: Go holds the close (`RegisterHook(WindowClosing)`, cancel,
  then close once done) and asks the page to save over the `open` stream, waiting for its report within a bound;
  the same on SIGTERM; the replaced connection served to its end before the new page is answered (a prototype
  with tests, red then green, is kept out of the tree, in the session scratchpad only; it lengthened
  WebKit reloads by the full bound, so it waits for the design). The presence goodbye (PR1) needs the same hold.
- **R-E2E1-2** → E2E1 UX-OI R19 step (above).
- **R-E2E1-3** closed by E2E2 (above) [done].
- **R-E2E1-4** closed by E2E2 (above) [done].
- **R-E2E2-1 → PR1 (P-1, P-3), WC1**: SHEET-MU-01b, the presence leaving on page close, is fixme on WebKit (above).

Sources: Wails v3.0.0 source (`pkg/application/webview_window.go`: hooks run in order and may cancel, listeners
run in goroutines; `linux_cgo.go`: `handleCloseRequest` always returns TRUE, the window is destroyed by
`gtk_window_destroy`); `@wailsio/runtime` 3.0.0 `dist/stream.js` (desktop streams are `fetch` POSTs without
`keepalive`, server builds a real WebSocket); WebKitGTK `webkit_web_view_try_close` (runs the page's unload
handlers, https://webkitgtk.org/reference/webkit2gtk/stable/method.WebView.try_close.html); `fetch` `keepalive`
for requests that outlive the page (https://developer.mozilla.org/en-US/docs/Web/API/RequestInit#keepalive);
automerge-repo 2.5.6 `Repo.flush` and its 100 ms `saveDebounceRate`. Measured here: a probe on WebKit showed
`pagehide`, `unload` and `sendBeacon` delivered on close, a plain `fetch` from `pagehide` not.
