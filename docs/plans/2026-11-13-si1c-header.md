Block SI1c, rigour standard, docs only at this step. Follows SI1b (accepted on its frozen gate; walkthrough
`gates/SI1b/UX.md` in the SI1b worktree). Closes UX-SI1b-1, UX-SI1b-2 (+ the OI walkthrough's 360 px header overlap),

replaced behaviour. Old title -> new title is the only edit to that test.

## SI1-C (display; replaces DS-3 and DS-5)
New display state `syncing`, « Synchronisation en cours », no count. `MixWindowMs` = 3000 (W).
- **C1:** while truth is `sending` or `behind`, if both kinds were true within the last W the target is `syncing`, else
  the truth's own label (pure behind « Pas encore à jour », pure sending « Envoi en cours (n) »).
- **C2:** entering goes through the old DS-3 hold (`MinShowMs`).
- **C3:** `syncing` yields to `synced` by DS-1 alone; to `sending`/`behind`/`checking` only after W without the other
  kind; a change to offline/alone shows at once.
- **C4 (honesty):** `synced` is never shown unless DS-1 holds; `syncing` is shown only if `sending` or `behind` was true
  within the last W (so it never outlives the truth by more than W); `synced` leaves at once (DS-2); n only on `sending`.
- **C5 (liveness):** constant truth shows itself within `MinShowMs + W` (non-synced) or `MinShowMs + SyncedHoldMs`.
Why: a longer hold only slows the metronome; merging removes it while both really happen (one « Saving… » in Google
Docs/Figma style save states). Rejected: « worst state held until typing stops » (needs a typing signal, hides sending).

## SI1-D (announcement)
`role="status"` stays polite and atomic (see Sources) with `aria-live="polite"` written out.
- **D1:** the live node holds only the label; the count and the « Lien lent » suffix are sibling `aria-hidden` spans
  (`data-testid="sync-count"`, `"sync-slow"`): never announced. « Lien lent » applies to `sending`, `behind`, `checking`
  and `syncing`.
- **D2:** no `aria-live="assertive"` in the header; among non-synced labels the live text changes at most once per
  `MinShowMs`, and under two typists once per regime.

## SI1-E (layout; container query on `.hb`, `container-type: inline-size`, `Wh` = header width)
Shrink order, the title never hidden (it names the document): (1) subtitle hidden below `Wh` 600; (2) title ellipsizes
(`min-width: 6ch`); (3) below 520 preview, present and history buttons move into the existing main menu (preview and
present entries exist; history is added, same pattern); (4) status label ellipsizes last (full text in `title`).
« Ellipsize the title first » is our choice (HIG/AdwWindowTitle say nothing); widget-width breakpoints are the
AdwBreakpointBin model. Reuses `.fb`, `MenuButton`, tokens; no new component (ux-principles §2, §9).
- **E1:** at viewport 360, 500, 700, 1024, sidebar open and closed: boxes of status, title (non-null, else fail) and end
  group pairwise disjoint and inside the viewport; status not clipped while title keeps >= 6ch; for `Wh < 520` the three
  buttons are absent and the menu holds their items, otherwise present (asserted in e2e: happy-dom ignores container
  queries).

## SI1-F (« Seul » and undelivered text, UX-SI1-3)
Rule: **never « Seul » while a local change is undelivered to anyone.** State, not events: `Unsent` <=> some change of
mine is outside the union of the heads last confirmed by any peer (model: `PendingOut(p)`,
`docs/protocol/tla/SyncIndicator.tla:195`, extended with `confirmed[p]`, kept across disconnects). No heads ever known
for a non-empty document (undecidable, e.g. first load) counts as unsent. Delivered to at least one person, even one who
left, is delivered: « Seul » is then honest.
Persistence: per document, the heads last confirmed received by a peer are stored through the existing per-document
store (`frontend/src/store/GoStorageAdapter.ts`, Go side `internal/store`, key `delivered/<docId>`), written when a
confirmation arrives; the flag is computed at load, so it survives restart.
| connected | other members | Unsent | header |
|---|---|---|---|
| 0, joining | any | any | « Connexion… » |
| 0 | none | any | « Seul » |
| 0 | >= 1 | no | « Seul » |
| 0 | >= 1 | yes | « Modifications non envoyées » (amber, state `unsent`) |
| >= 1 | any | any | indicator (SI1-C) |
Model: invariant `UnsentHonest` (flag shown <=> `Unsent` by state) and mutant `FlagFromEvents` (flag set by edit events,
cleared on reconnect) which it must catch; `model-SyncIndicator` joins the gate.

## Sources (fetched 2026-11-13 by the pre-freeze review; verdict per source)
- Verified: WAI-ARIA 1.2 status role https://www.w3.org/TR/wai-aria-1.2/#status: « Default for aria-live is polite.
  Default for aria-atomic is true. »
- Verified: WCAG 2.2 SC 4.1.3 https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html: status messages « can be
  programmatically determined through role or properties such that they can be presented [...] without receiving focus »;
  a status message includes information « on the waiting state of an application ».
- Verified: ARIA22 https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA22, « Using role=status to present status messages ».
- Verified (moved): MDN live regions, now https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Guides/Live_regions:
  assertive « should only be used for time-sensitive/critical notifications »; it advises a redundant
  `aria-live="polite"` on `role="status"` « to maximize compatibility ».
- Partly verified: GNOME HIG header bars https://developer.gnome.org/hig/patterns/containers/header-bars.html: « Header
  bars should only contain a small number of controls », which « ensures that the window can be resized to narrow widths »,
  and the content « can — and should — update along with view or mode changes ». It says nothing about ellipsizing, and
  neither does AdwWindowTitle's page: « the title ellipsizes first » is this plan's own choice, not a HIG rule.
- Verified: libadwaita adaptive layouts https://gnome.pages.gitlab.gnome.org/libadwaita/doc/main/adaptive-layouts.html
  (« depending on available size »; its example clears the header bar's title widget below 550sp), and widget-width
  breakpoints in AdwBreakpointBin https://gnome.pages.gitlab.gnome.org/libadwaita/doc/main/class.BreakpointBin.html: « Each
  breakpoint has a condition, specifying the bin's size and/or aspect ratio ».
- Verified: MDN container queries https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_containment/Container_queries:
  `container-type: inline-size`, « The query will be based on the inline dimensions of the container ».
- Not re-fetched (cited in the SI1 UX decisions): saasui.design autosave states, techinterview.org real-time liveness.
