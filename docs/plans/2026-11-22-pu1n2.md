# PU1n2 replaces PU1n

PU1n, frozen in `c7c90c7` on 2026-11-16, failed in its checker after the simulation passed. The checker glob for scenario 5 admitted `5-s20772-c5.json`, the `{counters, steps}` input to the C5 oracle introduced in `d051af2` on 2026-11-12, and attempted to read its `clauses` key. The same checker expected seeded clause JSON for scenarios 1–4, which have written only `1.txt` through `4.txt` under `.task/netsim/results` since `c97434c` on 2026-10-25. The runner has used and reset that directory since the same commit. Since `353eb5f` on 2026-11-08 it expands the seed list only for scenarios numbered 5 and higher and puts scenario 8's variant before the seed in the filename. That commit also introduced the Playwright `finish()` report writer for the impaired scenarios, which writes in either expectation mode. The first copy in PU1n found no JSON to copy, and the second run reset the text notes. The saved log shows four unseeded `PASS` rows at lines 205–210, then the three successful impaired runs at lines 276–283 and the checker exception at line 286. PU1n2 preserves the commands, seed settings, modes, timeouts and tolerance for declared known failures. It requires zero exits and one `PASS` row per strict scenario because the runner derives its status from stack setup and Playwright assertions and can return zero on a local skip before printing a summary. It reads only the three exact characterize report names, including both scenario 8 variants. HP1n (`dc16690`) also copies with a glob, but the checker opens exact names for 9, 6 and 7 and covers 1–4 through the strict invocation's exit code. The two PU1n checker defects therefore do not apply to HP1n. Review PU1n2 with a second model family and freeze it in its own commit before use.
