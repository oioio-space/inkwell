## Why a restart

Three designs changed the project inside the live session and each lost to a deeper race: (1) reset the adapter when
the bound call returns — the old coverage admits a head attested only under the old project until the reply arrives;
(2) pause the bridge stream, reset, let Go replay — frames already handed to automerge-repo continue after the pause
(`CollectionSynchronizer.receiveMessage` awaits `shareConfig.access` and `repo.find`; `removePeer` cancels nothing);
(3) the same on the Go side — `AdoptProject` clears the attestation store but not the 64-event buffer `w.out`
(`wiring.go:32`, `:191`, `:326`), `RecvEnvelope` revalidates PeerUp and Message only (`:734-739`), `Router.Run` picks
the connection after dequeuing (`router.go:103-111`), so an old `Attested` reaches the new stream after the replay.
A restart needs no ordering argument: the wiring, the bridge buffers, the adapter, the coverage, automerge-repo and
every pending continuation end with the process, and the next one loads only what is on disk.

Facts read in the code: nothing restarts or relaunches today (no `Exec`, no reload). `startup` (`cmd/inkwell/startup.go:69-112`)
claims the profile, runs the window, and returns after `stopAll` closed the network, the project and the instance
(`:145-151`); `/health` of the server build cannot tell an old image from a new one, hence the startup id; `Runtime.Close` stops the wiring before the invitation store (`internal/app/node.go:234-239`): the list
can be written between the two, when nothing can save an op any more. The Wails services are bound once, to one
`Session`, at `application.New` (`cmd/inkwell/main.go:113-121`): a runtime cannot be swapped inside the process, so the
restart is a new process image. `launch.Resolve` opens the project folder given as first argument when it is in the
Inkwell folder (`main.go:221-229`, rule R2 of OI): the restarted Inkwell reopens the same folder. The profile lock is a
`flock` (`internal/instance/lock_unix.go:13-21`), released by `stopAll` before the restart. A non-member is read-only
(N-3): at the time of a take-over the editor holds no text of its own to lose, and the stores are closed by the normal
shutdown. The e2e harness polls `/health` on the instance's port (`frontend/e2e/instance.ts`) and keeps the child's
pid; an exec in place changes neither the pid nor the process start time, so only the startup id proves a restart.

| N-12 | The restart. Each process image draws a random 128-bit **startup id** (`Session.StartupID()`, also in the e2e observe hook). `startup` restarts only when this image recorded a change request — a take-over (N-5) or a join (J-1) — once, after `stopAll` returned and N-14's barrier held. On Linux it executes `/proc/self/exe` — the running image itself, whatever became of its path (replaced or deleted by an upgrade) — with an argument list rebuilt from nothing: a fixed `argv[0]` and the absolute project folder; the environment is the current one without any `INKWELL_AFTER_TAKEOVER`, plus `INKWELL_AFTER_TAKEOVER=1`. The next image reads the variable once, removes it from its environment, and uses it only to choose a message from **the standing it actually loaded**: member -> « Ce document est maintenant le vôtre sur cet appareil. »; not a member -> « Le document n'a pas pu être repris. Rien n'a changé. ». The three outcomes of the write: failure before the install (old list: not a member), replace done, replace done with a finalisation error (`errCommitted`, `persist.go:80-85`: the new list is what loads: member, the error is logged). If the execution fails the runtime is already closed: the process notifies « Inkwell s'est fermé sans pouvoir redémarrer. Ouvrez-le de nouveau. » and exits with the error code; the list is on disk and the next launch loads it. No image then got the variable, so the process leaves a mark in the profile folder (`restart-failed`, holding the project folder; never in the project folder, which other devices see): the next launch that opens that folder takes the mark and says the same sentence from the standing it loaded, once (UX-PC1a-8). The restart page, which nothing reloads in that case, gives up after 15 s (three times N-14's 5 s; a restart measured 0.5 to 1.4 s) and shows the same « Inkwell s'est fermé… » sentence (`change.restartFailed`), still loading the application if an image answers later (UX-PC1a-2) | `TestRestartOnlyAfterARequestAndOnce` (both kinds), `TestRestartLosesLockToAnotherLaunch` (R-7: another launch takes the profile lock between the release and the re-acquisition; the restarted image hands its request over and exits, the next launch opens the changed folder), `TestRestartAfterStopAllReturned`, `TestRestartArgvAndEnvRebuilt` (misleading `argv[0]`, a stale variable in the environment), `TestRestartExecsTheRunningImage` (helper binary whose path is replaced, then deleted: the same image restarts, new startup id), `TestRestartFailureIsReported`, `TestRestartFailedThenLaunchedByHandSaysOnce`, `TestTakeOverOutcomeFollowsTheLoadedList` (the three outcomes: standing and message of the next start), `TestStartupNoticeShownOnce`; Vitest « PC1 the startup notice shows once and the text has the focus », « PC1 a failed take-over says so and stays readable », « PC1 the restart page gives up when no other image answers » (and its in-test mutant) | MW8 restart before `stopAll` returned -> `N-12 restart after the outcome`; MJ5 (PC1b) a join recorded without a restart -> `N-12 a join restarts`; model `JoinNoRestart` |
| N-13 | Shutdown ordering. From the request on (a held Welcome, J-1, included), `TakeOver`, `Join`, `Invite`, `InviteDevice` and `Ask` are refused (the session is leaving): one change per process image, so a take-over then a join, a join then a join, or a join then a take-over is refused until the restart. The write starts only when the wiring is closed, the lobby, the invitation host and any pending join have ended, and the blob service and discovery are stopped; it holds the invitation lock; nothing can then save an op to `.inkwell/trust` or sign under the old project; the trust store stays usable between `Wiring.Close` and its own close | `TestNoTrustWriteNorSignatureOnceTheWriteStarts` (a late op from each source — list sync, attestation, lobby, pending join — is refused; counting signer: zero), `TestRequestsRefusedOnceTakeOverRequested` (take-over then take-over, then join), `TestRequestsRefusedOnceJoinHeld` (PC1b: join then join, join then take-over), `TestTrustStoreUsableAfterWiringClose` | MW10 write before the lobby stopped -> `N-13 nothing writes once the write starts`; MW13 a second take-over accepted -> `N-13 one change per image`; MJ13 (PC1b) a second join accepted while one is held -> `N-13 one change per image` |
| N-14 | Termination barrier before the execution: every child and service the process started has ended (language service and tinymist, typst, the preview and asset servers, the peer-to-peer listeners, the instance socket), and every descriptor the process opened is close-on-exec; the new image starts with no descendant, no listening socket and no descriptor inherited beyond the standard three. The shutdown (`stopAll`) ends what the session started. What still runs then are children the process does not control (on the desktop build the web view's network and web processes and their sandbox holders, which live until the image's sockets close; UX-PC1a-1, 2026-11-15), whose work is over (N-15): the barrier does not wait for them, it ends them. The process makes itself a child subreaper (`PR_SET_CHILD_SUBREAPER`, prctl(2): what an ended helper leaves behind comes to it, not to init), sends SIGTERM to every child, reaps, sends SIGKILL to a child that still runs 100 ms later (the init of a sandbox's pid namespace takes no SIGTERM from outside, pid_namespaces(7)), and repeats until it has no child or 5 s have passed; it executes only with no child and no longer a subreaper (the attribute would survive the execution); past the 5 s it fails as an execution failure does (N-12), naming the children that still run | `TestRestartBarrier` (native, on the server binary with a preview and the language service started, and a helper the session does not control that leaves a process behind: only that helper is left to the barrier, both are ended; descendants, listening sockets and open descriptors counted before the request and read by the new image at its start; gate criterion `restart-barrier`); `TestEndChildren` (a child that ignores SIGTERM is killed after the grace; a process left by an ended child is reaped through the subreaper; the deadline failure names the survivor); the desktop build is checked in the walkthrough (`UX.md` states « orphans: 0 » from a process listing) | MW11 language service left running -> `N-14 no child survives`; MW16 the barrier only waits -> `N-14 remaining children are ended`; MW17 no subreaper -> `N-14 remaining children are ended` |
| N-15 | **The page leaves its context before the request, as best effort** (decided after Codex's round 1, softened after round 2, 2026-11-15: the proof that no write is lost or misapplied is Go's drain, N-16). After the confirmation (« Reprendre ce document ici ») or once Go holds a verified Welcome (« Rejoindre », J-1), the page (1) makes the editor read-only, (2) awaits `repo.flush()` and the pending file projection writes, with a 5 s deadline — past it, it sends nothing, calls `Session.CancelChange()` (a held Welcome is dropped), unlocks the editor and says « Le document n'a pas pu être enregistré. Rien n'a changé. » —, (3) awaits `repo.shutdown()`, then (4) `location.replace` to a static page, `restart.html` (its own Vite entry: no repo, adapter, editor, storage handle or store; it imports only the generated binding of `Session`), which shows « Inkwell redémarre… » and calls `Session.TakeOver()` or `Session.FinishJoin()`. These steps shorten the window in which the old page can still write; they are not trusted to close it (automerge-repo may still hold continuations), which is N-16's job. A peer's frame lost with the context is sent again by that peer at the next sync | Vitest « PC1 the page flushes, closes its repo and navigates before any request » (order of the spies), « PC1 a flush past its deadline sends nothing and changes nothing », « PC1 the restart page holds no repo, adapter or storage handle » (module graph of `restart.ts`); e2e « PC1-E2E nothing of the old session survives the restart » | in-test: request sent before the navigation -> N-15; model `RequestBeforeNavigation` |
| N-16 | **Go drains the bridge before it writes** (decided after Codex's round 2, 2026-11-15). On `TakeOver` or `FinishJoin`, before anything else, Go closes the bridge's `store` and `net` streams for good: one `bridge.Drain` shared by the two servers marks the session « leaving », so each open stream gets its end-of-stream, a write not yet taken by a handler is answered « refused » and the page shows « Le document n'a pas pu être enregistré. Rien n'a changé. », and every new stream is refused until the restart. Go then waits until every handler in flight has returned (a wait group in the registry, deadline 5 s). Only then do the shutdown of N-13, the member-list write and the restart run; past the deadline the request fails, nothing is written and the streams stay closed until the person quits. So every storage write of the page has either landed in the old project's storage (the next image finds it) or been refused with a sentence: never lost silently, never applied to the new project. Join points: the entry of `StoreServer.Serve` and of `Router.Serve` (`internal/bridge/storestream.go:402`, `internal/bridge/router.go:164`, registered by `cmd/inkwell/main.go:138-139`) refuse a new stream once leaving and add each served stream to the wait group; the read loop of `StoreServer.Serve` checks « leaving » before `s.handle(req)` (`storestream.go:443`: a request read after it is answered `refused`, one already in `handle` finishes and its reply is sent); `Router.Serve` does the same before dispatching a frame; `TakeOver` and `FinishJoin` call `Drain(ctx)` before recording the request | `TestStorageWriteBeforeRequestLandsOrIsRefused` (a write sent on the store stream just before `TakeOver`, its handler held by the test at each point — before taken, in the handler, after the reply: after the restart it is in Go storage, or the page got « refused »; never absent without a refusal; never under the new project), `TestChangeRequestClosesBridgeStreamsForGood` (store and net: end-of-stream, reopening refused until the restart), `TestChangeRequestFailsWhenDrainTimesOut` (a handler that never returns: request failed, list unchanged); PC1b: `TestStorageWriteBeforeFinishJoinLandsOrIsRefused` (the same on `FinishJoin`) | MW12 the member list written before the drain completes -> `N-16 no write before the drain`; model `WriteBeforeDrain` |

## Formal model

`docs/protocol/tla/ProjectChange.tla`, mutants `mutants/ProjectChangeMutants.tla`, registered in the README section
« ProjectChange » and in `scripts/tla-check.sh` (which also checks that TLC names the expected property). Actors: the
Go runtime of each process image (wiring and its event buffer, trust store, invitation host; shutdown, write,
barrier, restart, start), the page (coverage, automerge-repo continuations, root, startup id; the server build's tab,
which outlives the process), the restart by `Platform` (`exec` in place, or `spawn` of a process that claims the
profile lock, N35: the macOS and Windows ports implement the same rules), the environment (a peer, the person, a member
that gives the joined root, children, crashes, failed steps). Durable: the list and its staging siblings, the
record, `rootUrl`; everything else is lost by a crash or a restart. Safety: `NoOldStateAfterChange` (N-11, N-13,
N-14, N-15, J-1), `NoLostWrite` (N-16), `NewStateSurvives` (N-7, J-4), `RestartOnce`, `WriteBeforeRestart` (N-12, N-13), `OpensAfterCrash`
(N-7, J-1, J-4), `JoinOnce` (J-1, J-2), `OneImage` (N-12, N35), `NoticeMatchesStanding` (N-12, J-2); liveness
`ChangeCompletes` under three weak-fairness terms. Four sound configurations (exec and spawn; one or two crashes and
failed steps) hold exhaustively, 14,538 to 124,758 distinct states, 1 to 4 s each; thirteen mutants (`LiveAdopt`,
`RestartBeforeDurable`, `RestartTwice`, `RequestBeforeNavigation`, `JoinNoRestart`, `JoinTwice`, `WriteBeforeWiringStopped`, `NoBarrier`,
`SpawnNoWait`, `JoinRecordAfterInstall`, `RecoverPrefersAside`, `CarriedOutcome`, `PageNeverReloads`) are each caught
by the property of their row, and four witnesses (take-over, join with an announced root, crash after the install,
failed write) are reached. The model checks one change per run; the second request of an image is refused by N-13 and
held by its named tests (`TestRequestsRefusedOnceTakeOverRequested`, `TestRequestsRefusedOnceJoinHeld`, MW13, MJ13),
R-7's external launch by `TestRestartLosesLockToAnotherLaunch`, the archive by copy by `TestTakeOverArchivesOldList`
and MW6 (N-7); none of the three is claimed by the model. For a join the model's folder is the joined one (J-6): its
staging is the model's record and set-aside steps, its rename the install.

Residuals: R-6 of W58 (the live join) is closed by this block. **R-7** between the release of the profile lock and its re-acquisition by the restarted image another
launch can become the primary; the restarted one then hands its request over and exits (OI rule R10): the document is
taken over on disk and opens at the next launch. **R-8** the restart is specified for Linux; elsewhere
`restart_other.go` reports « unsupported » and the take-over is not offered (macOS and Windows: with their ports, which
implement the model's `spawn` restart, N35). A join there writes as on Linux, then Inkwell closes and asks to be opened
again (the person is the restart; the model's `Launch`): no platform keeps a live join. **R-9** after a failed execution the next manual launch opens the most recent project, which may
be another folder; the taken-over one opens normally when chosen. **R-10** a joined project whose members all stay away waits
(J-2): leaving it belongs to the Projects screen (R-4). **R-11** (rewritten after Codex's round 1) a join never writes the current
folder (J-6): the joined document gets its own folder beside it, and the previous text, with the edits flushed before
« Rejoindre » (N-15), stays where it was, opened from the Projects list or the file manager. R-1..R-5 as in the ADR.

That `application.App.Quit` runs `OnShutdown` in the server build as in the desktop one (`TestRestartAfterStopAllReturned`
runs on the real `deps`); the time from the confirmation to a writable editor, stated in the UX report (about one

Sources of step 1 (fetched 2026-11-15). systemd « offline updates »
(https://www.freedesktop.org/software/systemd/man/latest/systemd.offline-updates.html): a durable trigger consumed by
the next boot, removed « as early as possible » so that a failed update does not loop. J-1 takes the trigger and
rejects the early removal: removing the record before the root is held would let a crash open the old text under the
new list. A loop cannot happen here anyway, since consuming the record never restarts (`RestartOnce`). Electron's
relauncher (https://github.com/electron/electron/blob/main/shell/browser/relauncher.h): the parent starts a relauncher
that waits for the parent to exit before it launches the new image. The model's `spawn` gets that wait from ADR 0037's
profile lock instead of a pipe, and `SpawnNoWait` is that wait missing. Raft's TLA+ specification
(https://github.com/ongardie/raft.tla, `Restart`: « it loses everything but » stable storage): the idiom used here for
a crash and for a restart.
