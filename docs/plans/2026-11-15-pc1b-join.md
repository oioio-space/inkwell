## The join (rules J-1..J-6, written 2026-11-15, J-6 after Codex's round 1)

Today a join replaces the identity of a running session for any adoption of another project (`invites.go:379-419`),
and the three races of « Why a restart » apply to it. From this block an accepted invitation into another project ends
as the take-over does: nothing is written at the request, the new list is written during the shutdown under N-13's
ordering, Inkwell restarts (N-12, N-14, N-15), and the project of a running session is never changed. The joined
document gets **its own folder, beside the current one** (J-6): a join never writes the current folder's text or files.

| J-6 | **The joined document gets its own folder, beside the current one** (decided after Codex's round 1; naming and install made explicit after round 2, 2026-11-15: the title is supplied by a peer). The current folder's text and files are never written by a join. The folder is a new direct child of the current folder's parent. Its name comes from the joined document's title, normalised: Unicode NFC; only letters, digits, spaces and `-_.,()'` kept, every other character (path separators, control characters, NUL) removed; leading dots and spaces removed, so no dot-name (`.`, `..`, hidden); at most 64 characters, cut on a character boundary; « Document rejoint » when nothing is left. The content is written first into a staging folder in the same parent (`.inkwell-join-<record id>`, J-1's 128-bit random id, created with exclusive create), synced, then installed by one rename **that never replaces** (`renameat2(RENAME_NOREPLACE)` on Linux, `renamex_np(RENAME_EXCL)` on macOS, `MoveFileExW` without `MOVEFILE_REPLACE_EXISTING` on Windows); when the name is taken the rename fails and the next name, « (2) », « (3) »… up to 99, is tried; past that the join fails with J-4's sentence. Before the staging folder is created, a marker in the previous folder, `.inkwell/join-pending.json` (`{v: 1, id}`, by `store.WriteAtomic`), names it: the marker is the one way the previous folder finds the staging folder after an interruption (one location, decided after Codex's round 3). A crash before the rename leaves the previous folder as it was and its next start removes the staging folder, then the marker (J-4); a crash after it opens the joined folder, and the next start of the previous folder removes the marker only, the staging name being gone. A peer's title can therefore name nothing but a new direct child of the parent. The previous text, with the edits flushed before « Rejoindre » (N-15) and drained by Go (N-16), stays in its folder, opened from the Projects list or the file manager | `TestJoinKeepsThePreviousFolder` (tree hash of the previous folder without `.inkwell` equal before `Join`, after the restart and after the first save of the joined document), `TestJoinFolderNameConfined` (titles `../x`, `a/b`, `a\\b`, `.`, `..`, `.hidden`, NUL, control characters, 500 characters, only forbidden characters: always a new direct child of the parent with the normalised or default name), `TestJoinFolderCollisionGetsSuffix` (the name exists as a folder, as a file, and as a symbolic link: never replaced, never followed, « (2) » used; 99 taken: the join fails, nothing changed), `TestJoinCrashDuringInstall` (a crash after the marker, before the rename, after it, and with the staging folder half written: the previous folder unchanged but for the marker, the staging folder and then the marker removed at the next start, the joined folder complete or absent; a marker naming a missing folder is removed alone) | MJ12 the joined document projected into the current folder -> `J-6 previous folder unchanged`; MJ14 the title used unsanitised -> `J-6 folder name confined`; MJ15 the install rename replaces an existing folder -> `J-6 never replaces`; MJ16 the staging folder created before the marker -> `J-6 staging found again` |
