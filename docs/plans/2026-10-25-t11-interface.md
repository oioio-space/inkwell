# T11 — Interface complète : implémentation et matrice de cas

> **Pour les agents :** sous-skill requis `superpowers:subagent-driven-development`. Les étapes
> utilisent des cases à cocher (`- [ ]`). Chaque cas de la matrice d'une tâche a **son** test,
> nommé par son identifiant (`it("FMT-07 …")`, `func TestFormat/FMT-07`). Une tâche est terminée
> quand tous ses cas passent et que `mise run ci` est vert. Un cas sans test, ou un test sans
> assertion sur le résultat visible, bloque la revue.

**Objectif :** livrer l'interface de la maquette v3 avec chacune de ses fonctions. Chaque
fonction est prouvée par des tests qui couvrent ses cas : qui agit, dans quel état, avec quelle
entrée, et ce qui doit en résulter (données, affichage, réseau, historique, annulation).

**Architecture :** les commandes d'édition sont des fonctions pures sur `EditorState` (CodeMirror 6)
par langage. L'UI est en Svelte 5, aux jetons libadwaita 1.8. Go reste un transporteur d'octets
opaques et le gardien du disque (encodage, fins de ligne, surveillance). Droits, verrous et
déconnexions passent par des opérations signées (`trust`), vérifiées par chaque pair (comme T10).

**Pile :** CodeMirror 6, Automerge 3.5 / automerge-repo 2.5, Svelte 5, Vitest + fast-check
(propriétés), Playwright (2 à 3 instances, mode serveur), Go 1.27 (`testing`, `synctest`,
fuzz), tinymist/typst en sidecar (vague C).

**Spécification :**
- maquette v3 : https://claude.ai/artifact/GrDQdXpfqirmnjgcuBtHjm ;
- `docs/conception.pdf` (§ Édition, § Présentations, § Principes UX) ;
- exigences utilisateur (2026-10-25) :
  - barre selon le format, avec code en ligne **et** bloc ;
  - menu Insérer ;
  - fichiers modifiés hors d'Inkwell intégrés ;
  - enregistrement automatique **ou** Ctrl+S, au choix ;
  - icônes de fichiers ;
  - bande de modifications ;
  - historique et variantes ;
  - zones verrouillées ;
  - déconnecter et laisser revenir ;
  - présentations avec vue présentateur.

## Contraintes globales

- Les invariants de `CLAUDE.md`, en particulier :
  - CRDT dans la webview ;
  - aucun port local hors `127.0.0.1` avec jeton ;
  - « personne » dans l'UI, jamais « pair ».
- Zéro jargon : chaque libellé dit ce qui se passe (« Joindre un fichier au PDF — voyage dans
  le PDF sans s'afficher »). Les textes vivent dans `i18n/fr.json`, avec `en.json` à parité (test
  existant).
- Les jetons viennent de libadwaita 1.8 (`theme/tokens.css`), clair et sombre. Cibles ≥ 34 px dans
  les barres et ≥ 44 px dans les dialogues ; focus clavier visible ; `prefers-reduced-motion`
  respecté.
- Chaque action d'édition est **une** transaction CodeMirror, donc un seul pas d'annulation, propagé
  comme une frappe ordinaire.
- Rien ne détruit l'historique : « revenir », « fusionner », « abandonner » et « déconnecter »
  ajoutent des opérations.
- Le code Typst cible **Typst 0.15** et **Touying 0.7.4** :
  - `#pdf.attach` remplace `pdf.embed`, supprimé en 0.14 ;
  - les notes d'orateur s'écrivent `#speaker-note[…]`.
- Tout décodeur d'octets venus d'un pair ou du disque est fuzzé.

## Axes de la matrice de cas (à parcourir pour chaque fonction)

| Axe | Valeurs |
|-----|---------|
| **Qui** | créatrice · admin · écrivain · lecteur · déconnecté · retiré · inconnu · pair modifié (malveillant) |
| **État réseau** | seul · direct LAN · relais · hors ligne puis retour · deux éditions concurrentes · trois pairs |
| **Entrée** | vide · curseur sans sélection · sélection · sélection multi-lignes · multi-curseurs · déjà formaté · formaté partiellement · imbriqué · Unicode (accents composés, emoji ZWJ, CJK, RTL) · CRLF · très gros fichier (5 Mo) |
| **Résultat** | texte Automerge · affichage (DOM, focus, aria) · fichier disque · historique · annulation (Ctrl+Z / Ctrl+Maj+Z) · ce que voient les autres pairs |

Chaque matrice ci-dessous en est la projection utile. Les cas « … chez l'autre pair » sont des
e2e à deux instances (`frontend/e2e/`) ; les autres sont des tests unitaires ou de propriété.

### B1 · Enregistrement et modifications hors d'Inkwell (TS + Go)

**Comportement.** L'historique Automerge est toujours persisté (`store`). Le réglage décide
seulement quand le fichier projeté est réécrit :
- `auto` : `PROJECTION_DELAY_MS`, 1 s par défaut ;
- `manual` : Ctrl+S.

Un changement extérieur est intégré par `A.changeAt(doc, headsAuDernierSyncDisque, d =>
A.updateText(d, ["text"], nouveauTexte))`, puis fusionné. Les frappes concurrentes des autres sont
ainsi préservées. Les lignes venues du disque sont marquées. Le toast « Modifié hors d'Inkwell :
N lignes intégrées · Voir · Annuler » remplace la boîte Importer/Ignorer actuelle
(`ExternalChangeToast.svelte`).

**Produit :**
- `saveMode` (préférence par projet) ;
- `workspace.save()` ;
- `dirty` : « Non enregistré » dans la barre d'état et un point dans le titre ;
- `lastDiskHeads` persisté avec le hash disque (`project.record`) ;
- `mergeExternal(name)`, `undoExternal()`.

### B2 · Bande de modifications, historique, versions, variantes (TS)

**Modèle.**
- **Dernière visite :** heads mémorisées localement par personne et par document (`store`, clé
  `visit/<doc>`).
- **Versions nommées :** `doc.meta.versions: {name, heads, by, at}[]`, signées par l'auteur
  (l'opération Automerge porte son acteur, vérifié par T10).
- **Variantes :** chaque variante est un document automerge-repo séparé, créé par
  `A.clone(main, au point choisi)`. Elle est listée dans `doc.meta.variants: {url, name, from,
  by, state: open|merged|abandoned}[]`.
  - **Fusionner** = `handle.merge(variante)` dans la principale, avec une version nommée
    automatique « Avant fusion de X ».
  - **Abandonner** = l'état passe à `abandoned` ; le document est conservé.
- **Revenir à une version :** `A.updateText` vers le texte à ces heads, en **une** modification.
  Rien n'est effacé.
- **Groupement par séances :** suite de changements d'un même acteur, sans pause de plus de 10 min.

**Produit :**
- `changeGutter(sinceHeads, by: "type"|"person")` : extension CodeMirror (`GutterMarker` ajouté,
  modifié, supprimé) avec une minicarte dans la barre de défilement ;
- `history(doc) → Session[]` ;
- `nameVersion`, `revertTo`, `fork`, `mergeVariant`, `abandonVariant` ;
- `HistoryPanel.svelte`, qui dessine le graphe en SVG, comme dans la maquette.

**Matrice :**

| HIS-02 | un pair ajoute, modifie et supprime pendant mon absence | vert, bleu et triangle rouge aux bonnes lignes ; minicarte cohérente |
| HIS-03 | « par personne » | couleur de l'auteur (palette de présence) ; infobulle « Marie, 14:10 » |

### B3 · Droits : déconnecter et laisser revenir, zones verrouillées, gestion des personnes

**Conception d'abord (architect, Opus).** Deux nouvelles ADR précèdent le code :
- ADR 0021 « Suspension » : opérations `suspend(peer)` et `resume(peer)` dans la liste signée ;
- ADR 0022 « Zones verrouillées » : `lock{doc, debut, fin}` ancré par curseurs Automerge, puis
  `unlock`.

Chacune précise l'application chez un client honnête, la vérification par les pairs (rejet des
modifications non autorisées, comme T10) et les cas d'attaque. Un audit (security-auditor) suit.

**Comportement.**
- **Déconnecter :** les pairs coupent le lien et refusent la synchronisation du suspendu. Ses
  modifications hors ligne restent chez lui et sont refusées tant qu'il est suspendu. **Laisser
  revenir** les accepte ensuite (opération `resume`). Les droits restent ceux d'avant.
- **Retirer :** définitif, comme la suppression existante.
- **Verrou :** seul un admin pose ou lève un verrou. Un non-admin qui tape dedans est bloqué
  localement (`EditorState.changeFilter`) ; une modification forgée est rejetée par les pairs.
  « Proposer un changement » crée une suggestion qu'un admin accepte ou refuse.

### B4 · Projet multi-fichiers : ce que reçoit une personne qui rejoint

**Constat.** Aujourd'hui, seul `main.typ`, document racine, est synchronisé. Un projet réel
compte d'autres fichiers :
- des chapitres `.typ` ou `.md` ;
- des images, des PDF, des `.csv`, des `.bib` ;
- des polices ;
- des paquets `@preview` dans `.typstdeps/`.

**Modèle (ADR 0023, à faire valider par architect avant le code).**
- Un **index de projet** Automerge `{files: {chemin → {kind, url (texte) | hash (binaire), size,
  by, at}}}` fait foi pour l'arborescence.
- Chaque fichier texte est son propre document automerge-repo, référencé par `url`.
- Chaque fichier binaire est désigné par son hash BLAKE3 et transféré par le magasin `blob`
  (étape 4, avancé ici) : morceaux vérifiés, quotas, reprise.
- Les paquets `.typstdeps/` et les polices du projet sont des binaires comme les autres.
- Créer, renommer, déplacer et supprimer sont des opérations sur l'index. Une suppression va à la
  corbeille du projet ; elle est restaurable.

**Produit :**
- `ProjectIndex` (TS) : `add`, `rename`, `remove`, `restore` ;
- Go : `blob.Put`, `blob.Get` et l'échange libp2p (canal mux dédié), qui vérifie le hash avant
  l'écriture ;
- `Sidebar` : progression « Réception : 12 sur 40 fichiers, 3,2 Mo ».

**Matrice :**

| Id | Cas | Attendu |
|----|-----|---------|
| PRJ-01 | rejoindre un projet de 40 fichiers (texte, images, PDF, CSV, `.bib`, polices, `.typstdeps`) | les 40 arrivent ; arborescence identique ; hashes identiques ; le projet compile chez l'arrivant sans réseau (e2e + comparaison d'arborescence) |
| PRJ-02 | rejoindre puis couper le réseau à 50 % du transfert | reprise sans retransmettre ce qui est déjà vérifié ; « 20 sur 40 » affiché ; pas de fichier à moitié écrit visible |
| PRJ-03 | binaire falsifié par un pair modifié | hash refusé, fichier redemandé à un autre pair ; journal de sécurité |
| PRJ-04 | fichier ajouté après l'arrivée | apparaît chez tous, avec la bonne icône |
| PRJ-05 | A renomme `ch1.typ` pendant que B l'édite | B continue dans le même document (l'url ne change pas) ; les `#include` ne sont pas réécrits automatiquement, mais un avertissement « référence cassée » est affiché avec un lien de correction |
| PRJ-06 | A supprime un fichier pendant que B l'édite | B voit un bandeau « supprimé par A — Restaurer » ; ses frappes ne sont pas perdues (le document existe toujours, dans la corbeille) |

## B5 · Gestionnaire de fichiers (demande du 2026-10-25, 20:30)

**Principe.** La liste des fichiers est un vrai gestionnaire de fichiers. Chaque action est une
modification de l'index (ADR 0023), répliquée chez tous et inscrite dans l'historique. Rien ne
disparaît sans accord.

**Actions :**
- nouveau fichier (avec un modèle : Typst, Markdown, texte) ;
- nouveau dossier ;
- importer depuis le disque, en glissant depuis le bureau ou par un sélecteur ;
- renommer en place (F2) ;
- déplacer par glisser-déposer ;
- dupliquer ;
- copier le chemin ;
- ouvrir dans le gestionnaire du système ;
- définir le fichier principal ;
- supprimer, restaurer, vider la corbeille.

Pour la sélection multiple : Ctrl, Maj, et Suppr au clavier.

**Suppression avec accord.** C'est un réglage du projet, « Supprimer un fichier : sur accord d'un
administrateur (par défaut) · librement ».
- Un écrivain qui supprime crée une **demande de suppression** : `nodes[id].deletion = {by, at}`. Le
  fichier reste visible, barré, avec un bandeau. Les admins voient « Paul demande à supprimer
  ch2.typ — Accepter · Refuser ».
- Accepter met le fichier dans la corbeille ; refuser retire la demande.
- Un admin qui supprime met directement le fichier dans la corbeille.
- La corbeille garde tout jusqu'à « Vider la corbeille », réservé aux admins et confirmé. Même vidée,
  la corbeille ne fait rien disparaître de l'historique :
  - pour un texte, le document Automerge est conservé ;
  - pour un binaire, il est gardé 30 jours (ADR 0023).
- **Historique.** Le panneau Historique montre chaque opération sur les fichiers : « Paul a créé /
  renommé / déplacé / demandé la suppression de… », « Alice a accepté… ». Chacune propose
  « Restaurer » ou « Revenir ».

## B6 · Rechercher et remplacer (demande du 2026-10-25, 20:44)

**Modèle :** la fenêtre de résultats de Notepad++. Le moteur est pur TS
(`frontend/src/editor/search/`) ; le panneau vient avec A4.

**Champ de recherche.**
- Ctrl+F dans le fichier, Ctrl+Maj+F dans tout le projet. Ctrl+H ouvre le remplacement.
- Trois modes : **Normal** (texte littéral, avec les échappements `\n` et `\t` en option « étendu »),
  **Joker** (`*` = n'importe quelle suite sur la ligne, `?` = un caractère, `[abc]` = un caractère
  parmi), **Regex** (JS, drapeau `u`, plus l'option « `.` inclut les retours à la ligne »).
- Options : respecter la casse ; mot entier (désactivé en Regex) ; ignorer les accents (« e »
  trouve « é ») ; dans la sélection ; boucler.
- Filtres de fichiers pour la recherche dans le projet : `*.typ *.md !brouillons/`.

**« Tout trouver ».** Un panneau en bas liste les résultats.
- Regroupement par fichier, puis par ligne, avec le numéro de ligne et le mot trouvé surligné.
- Les lignes longues sont tronquées autour de l'occurrence.
- Clic ou Entrée : saut à l'occurrence (le fichier s'ouvre si besoin, l'occurrence est sélectionnée et
  centrée). F3 et Maj+F3 passent au résultat suivant ou précédent ; F4 et Maj+F4 aussi depuis
  l'éditeur.
- Groupes repliables, compteur « 37 résultats dans 5 fichiers ».
- « Chercher dans ces résultats ». Copier les lignes trouvées.
- Les recherches précédentes restent dans le panneau, empilées, jusqu'à « Effacer ».
- Les résultats suivent les modifications : une occurrence modifiée par quelqu'un est grisée, jamais
  un mauvais saut.

**Remplacer.**
- Remplacer, ou tout remplacer (dans le fichier, la sélection ou le projet).
- En Regex, les groupes s'écrivent `$1` et `$<nom>`.
- Un aperçu avant/après est montré avant de tout remplacer dans le projet.
- **Une seule modification par fichier**, donc un seul Ctrl+Z.
- Les zones verrouillées sont respectées (ADR 0022) : les occurrences qui y tombent sont comptées à
  part et non remplacées, sauf pour un admin.
- Un lecteur ne peut que chercher.

## B7 · Documents liés : inclusions, références, présence (demandes du 2026-10-25, 21:03 et 21:04)

**Principe.**
- Un projet est un graphe de fichiers. Inkwell connaît chaque lien, entre fichiers comme vers un
  point précis d'un fichier, et l'exploite pour éditer, naviguer et compiler. Le tout fonctionne
  hors ligne.
- Seuls les liens **internes au projet** sont vérifiés.
- Les adresses externes (`https://…`, `mailto:`) ne sont **jamais** testées : aucune requête réseau,
  ni à l'édition ni au clic. Elles ont un style neutre « lien externe ».

**Analyse des liens** (`frontend/src/editor/links/`).
- Typst : extraction depuis l'arbre `codemirror-lang-typst` (A5) de :
  - `#include "…"`, `#import "…"` ;
  - `image("…")`, `read("…")`, `csv("…")`, `json/yaml/toml("…")` ;
  - `#bibliography("…")`, `#pdf.attach("…")` ;
  - `#link("…")` (fichier local ou `<étiquette>`) ;
  - les étiquettes `<x>` et les références `@x`.

  Plus tard, la vague C rendra l'analyse exacte avec tinymist et `typst query`.
- Markdown :
  - `[t](chemin.md)`, `[t](chemin.md#titre)`, `![](image.png)` ;
  - références `[t][id]` ;
  - ancres de titres (slug GFM).
- Chemins résolus relativement au fichier, ou à la racine du projet s'ils commencent par `/`, comme
  Typst. Validés par les mêmes règles que les noms (ADR 0023).
- **Graphe du projet :** inclusions et imports forment un arbre de documents depuis le fichier
  principal. Il sert au plan latéral (titres de tous les chapitres inclus), aux étiquettes et aux
  renvois de tout le projet, et à la compilation (vague C).

**Affichage dans l'éditeur.**
- Chaque lien interne porte un état :
  - **présent** : souligné discret ;
  - **absent** : souligné ondulé rouge, avec « Fichier introuvable : figures/plan.svg » et deux
    actions, « Créer » et « Choisir un fichier… » ;
  - **en cours de réception** : grisé, « en cours de réception » (B4) ;
  - **dans la corbeille** : « dans la corbeille — Restaurer ».
- Ctrl+clic, ou Alt+Entrée au clavier :
  - vers un fichier, l'ouvre ;
  - vers une étiquette ou un titre, va à sa définition, même dans un autre fichier ;
  - vers une adresse externe, ouvre le navigateur du système, sans aucune vérification.
- Survol d'une image : vignette. Survol d'un `#include` : les premières lignes. Survol d'une
  référence : le titre ou la légende ciblés.
- Barre de mise en forme, « Insérer › Renvoi » et « Lien vers un fichier » :
  - un sélecteur avec recherche floue ;
  - pour les fichiers : nom, icône, dossier ;
  - pour les étiquettes et titres : de tout le projet, avec le fichier d'origine ;
  - pour les citations : clés `.bib`.
- Autocomplétion en tapant `@`, `#include "`, `image("` ou `](`.
- Panneau « Liens » de la barre latérale :
  - pour le fichier courant, ce qu'il utilise (sortants, avec leur état) et qui l'utilise
    (entrants, « rétroliens ») ;
  - un compteur « 2 liens cassés » dans la barre d'état, cliquable.
- Renommer ou déplacer un fichier propose de **mettre à jour les liens** qui le visent, dans tout le
  projet : aperçu, une modification par fichier, refus dans les zones verrouillées (comme SRC-16).

**Présence dans la liste des fichiers.**
- À côté de chaque fichier, les pastilles des personnes qui l'ont **ouvert**, à leur couleur. La
  pastille est pleine si la personne tape en ce moment, en contour si elle lit.
- Infobulle : « Paul y écrit — ligne 47 », « Marie le lit ».
- Un dossier replié agrège les pastilles de son contenu.
- Un point « modifié depuis votre dernière visite » sur les fichiers changés par d'autres (B2).
- La présence voyage par l'éphémère automerge-repo (déjà utilisé pour les curseurs). Elle n'est
  jamais enregistrée (conception, § Présence) et disparaît quand la personne ferme le fichier ou
  se déconnecte.

## B8 · Mise en page des fichiers Markdown (demande du 2026-10-25, 21:05)

**Constat.** Un fichier Typst porte sa propre mise en page ; un fichier Markdown n'en a aucune. On
choisit donc une mise en page par fichier, et l'aperçu comme l'export l'appliquent.

**Deux familles, au choix dans le menu « Mise en page » (barre d'état, à côté du langage) :**
1. **Mise en page Typst (pour imprimer et exporter en PDF).**
   - Le Markdown est rendu par Typst à travers le paquet [cmarker](https://typst.app/universe/package/cmarker),
     épinglé et fourni avec le projet (ADR 0023 `.typstdeps`), dans un modèle Typst.
   - Modèles fournis : « Note », « Rapport » (page de titre, table des matières, numérotation),
     « Lettre », « Procédure » (encadrés pour `> **Attention**`), « Diapositives » (Touying : `---`
     sépare les diapositives).
   - Un modèle personnel est n'importe quel fichier `.typ` du projet qui exporte
     `#let template(doc) = …`. Il est proposé automatiquement dans le menu.
   - L'aperçu est celui de Typst (pages, saut source ↔ aperçu), donc identique au PDF exporté.
2. **Feuille de style CSS (pour lire à l'écran et exporter en HTML).**
   - Styles fournis : « Adwaita », « Lecture » (serif, colonne de 70 caractères), « GitHub »,
     « Imprimable A4 » (`@page`, marges, sauts de page avant `h1`).
   - Un style personnel est n'importe quel fichier `.css` du projet.
   - L'aperçu est le HTML dans une iframe **isolée**, sans script : `sandbox` sans `allow-scripts`,
     et CSP `default-src 'none'` ; seules les images du projet sont permises, par URL `blob:`.
   - Le CSS du projet est assaini avant usage : pas de `@import`, pas d'`url()` hors du projet, pas
     de police distante. Il vient d'autres pairs, et le rendu doit rester hors ligne.
   - Le Markdown est converti par un analyseur CommonMark + GFM. Le HTML brut est assaini (liste
     blanche), sans `script`, sans `on*` et sans `javascript:`.

**Où vit le choix.**
- Le choix est un attribut du nœud dans l'index du projet : `layout = {engine: "typst"|"css",
  name|path}`. Il est donc répliqué, il entre dans l'historique, et le fichier `.md` reste propre,
  sans en-tête ajouté.
- Il existe une mise en page par défaut du projet pour les nouveaux fichiers.
- Si le fichier a déjà un en-tête YAML avec `title`, `author` ou `date`, ces valeurs sont passées au
  modèle Typst et au HTML, comme le fait pandoc.

**Export.** « Exporter » produit, selon la famille :
- **Typst :** un PDF, avec les pièces jointes et les polices ;
- **CSS :** un HTML autonome (CSS et images intégrés), ou un PDF par le moteur d'impression de la
  webview.
