# T11 — Interface complète : implémentation et matrice de cas

> **Pour les agents :** sous-skill requis `superpowers:subagent-driven-development`. Les étapes
> utilisent des cases à cocher (`- [ ]`). Chaque cas de la matrice d'une tâche a **son** test,
> nommé par son identifiant (`it("FMT-07 …")`, `func TestFormat/FMT-07`). Une tâche est terminée
> quand tous ses cas passent et que `mise run ci` est vert. Un cas sans test, ou un test sans
> assertion sur le résultat visible, bloque la revue.

**Objectif :** livrer l'interface de la maquette v3 avec chacune de ses fonctions. Chaque
fonction est prouvée par des tests qui couvrent ses cas : qui agit, dans quel état, avec quelle
entrée, et ce qui doit en résulter (données, affichage, réseau, historique, annulation).

**Architecture :** les commandes d'édition sont des fonctions pures sur `EditorState` (CodeMirror 6)
par langage. L'UI est en Svelte 5, aux jetons libadwaita 1.8. Go reste un transporteur d'octets
opaques et le gardien du disque (encodage, fins de ligne, surveillance). Droits, verrous et
déconnexions passent par des opérations signées (`trust`), vérifiées par chaque pair (comme T10).

**Pile :** CodeMirror 6, Automerge 3.5 / automerge-repo 2.5, Svelte 5, Vitest + fast-check
(propriétés), Playwright (2 à 3 instances, mode serveur), Go 1.27 (`testing`, `synctest`,
fuzz), tinymist/typst en sidecar (vague C).

**Spécification :**
- maquette v3 : https://claude.ai/artifact/GrDQdXpfqirmnjgcuBtHjm ;
- `docs/conception.pdf` (§ Édition, § Présentations, § Principes UX) ;
- exigences utilisateur (2026-10-25) :
  - barre selon le format, avec code en ligne **et** bloc ;
  - menu Insérer ;
  - fichiers modifiés hors d'Inkwell intégrés ;
  - enregistrement automatique **ou** Ctrl+S, au choix ;
  - icônes de fichiers ;
  - bande de modifications ;
  - historique et variantes ;
  - zones verrouillées ;
  - déconnecter et laisser revenir ;
  - présentations avec vue présentateur.

## Contraintes globales

- Les invariants de `CLAUDE.md`, en particulier :
  - CRDT dans la webview ;
  - aucun port local hors `127.0.0.1` avec jeton ;
  - « personne » dans l'UI, jamais « pair ».
- Zéro jargon : chaque libellé dit ce qui se passe (« Joindre un fichier au PDF — voyage dans
  le PDF sans s'afficher »). Les textes vivent dans `i18n/fr.json`, avec `en.json` à parité (test
  existant).
- Les jetons viennent de libadwaita 1.8 (`theme/tokens.css`), clair et sombre. Cibles ≥ 34 px dans
  les barres et ≥ 44 px dans les dialogues ; focus clavier visible ; `prefers-reduced-motion`
  respecté.
- Chaque action d'édition est **une** transaction CodeMirror, donc un seul pas d'annulation, propagé
  comme une frappe ordinaire.
- Rien ne détruit l'historique : « revenir », « fusionner », « abandonner » et « déconnecter »
  ajoutent des opérations.
- Le code Typst cible **Typst 0.15** et **Touying 0.7.4** :
  - `#pdf.attach` remplace `pdf.embed`, supprimé en 0.14 ;
  - les notes d'orateur s'écrivent `#speaker-note[…]`.
- Tout décodeur d'octets venus d'un pair ou du disque est fuzzé.

## Axes de la matrice de cas (à parcourir pour chaque fonction)

| Axe | Valeurs |
|-----|---------|
| **Qui** | créatrice · admin · écrivain · lecteur · déconnecté · retiré · inconnu · pair modifié (malveillant) |
| **État réseau** | seul · direct LAN · relais · hors ligne puis retour · deux éditions concurrentes · trois pairs |
| **Entrée** | vide · curseur sans sélection · sélection · sélection multi-lignes · multi-curseurs · déjà formaté · formaté partiellement · imbriqué · Unicode (accents composés, emoji ZWJ, CJK, RTL) · CRLF · très gros fichier (5 Mo) |
| **Résultat** | texte Automerge · affichage (DOM, focus, aria) · fichier disque · historique · annulation (Ctrl+Z / Ctrl+Maj+Z) · ce que voient les autres pairs |

Chaque matrice ci-dessous en est la projection utile. Les cas « … chez l'autre pair » sont des
e2e à deux instances (`frontend/e2e/`) ; les autres sont des tests unitaires ou de propriété.

### B1 · Enregistrement et modifications hors d'Inkwell (TS + Go)

**Comportement.** L'historique Automerge est toujours persisté (`store`). Le réglage décide
seulement quand le fichier projeté est réécrit :
- `auto` : `PROJECTION_DELAY_MS`, 1 s par défaut ;
- `manual` : Ctrl+S.

Un changement extérieur est intégré par `A.changeAt(doc, headsAuDernierSyncDisque, d =>
A.updateText(d, ["text"], nouveauTexte))`, puis fusionné. Les frappes concurrentes des autres sont
ainsi préservées. Les lignes venues du disque sont marquées. Le toast « Modifié hors d'Inkwell :
N lignes intégrées · Voir · Annuler » remplace la boîte Importer/Ignorer actuelle
(`ExternalChangeToast.svelte`).

**Produit :**
- `saveMode` (préférence par projet) ;
- `workspace.save()` ;
- `dirty` : « Non enregistré » dans la barre d'état et un point dans le titre ;
- `lastDiskHeads` persisté avec le hash disque (`project.record`) ;
- `mergeExternal(name)`, `undoExternal()`.

### B2 · Bande de modifications, historique, versions, variantes (TS)

**Modèle.**
- **Dernière visite :** heads mémorisées localement par personne et par document (`store`, clé
  `visit/<doc>`).
- **Versions nommées :** `doc.meta.versions: {name, heads, by, at}[]`, signées par l'auteur
  (l'opération Automerge porte son acteur, vérifié par T10).
- **Variantes :** chaque variante est un document automerge-repo séparé, créé par
  `A.clone(main, au point choisi)`. Elle est listée dans `doc.meta.variants: {url, name, from,
  by, state: open|merged|abandoned}[]`.
  - **Fusionner** = `handle.merge(variante)` dans la principale, avec une version nommée
    automatique « Avant fusion de X ».
  - **Abandonner** = l'état passe à `abandoned` ; le document est conservé.
- **Revenir à une version :** `A.updateText` vers le texte à ces heads, en **une** modification.
  Rien n'est effacé.
- **Groupement par séances :** suite de changements d'un même acteur, sans pause de plus de 10 min.

**Produit :**
- `changeGutter(sinceHeads, by: "type"|"person")` : extension CodeMirror (`GutterMarker` ajouté,
  modifié, supprimé) avec une minicarte dans la barre de défilement ;
- `history(doc) → Session[]` ;
- `nameVersion`, `revertTo`, `fork`, `mergeVariant`, `abandonVariant` ;
- `HistoryPanel.svelte`, qui dessine le graphe en SVG, comme dans la maquette.

**Matrice :**

| HIS-02 | un pair ajoute, modifie et supprime pendant mon absence | vert, bleu et triangle rouge aux bonnes lignes ; minicarte cohérente |
| HIS-03 | « par personne » | couleur de l'auteur (palette de présence) ; infobulle « Marie, 14:10 » |
| HIS-04 | je tape | mes propres frappes ne sont pas marquées |

### B3 · Droits : déconnecter et laisser revenir, zones verrouillées, gestion des personnes

**Conception d'abord (architect, Opus).** Deux nouvelles ADR précèdent le code :
- ADR 0021 « Suspension » : opérations `suspend(peer)` et `resume(peer)` dans la liste signée ;
- ADR 0022 « Zones verrouillées » : `lock{doc, debut, fin}` ancré par curseurs Automerge, puis
  `unlock`.

Chacune précise l'application chez un client honnête, la vérification par les pairs (rejet des
modifications non autorisées, comme T10) et les cas d'attaque. Un audit (security-auditor) suit.

**Comportement.**
- **Déconnecter :** les pairs coupent le lien et refusent la synchronisation du suspendu. Ses
  modifications hors ligne restent chez lui et sont refusées tant qu'il est suspendu. **Laisser
  revenir** les accepte ensuite (opération `resume`). Les droits restent ceux d'avant.
- **Retirer :** définitif, comme la suppression existante.
- **Verrou :** seul un admin pose ou lève un verrou. Un non-admin qui tape dedans est bloqué
  localement (`EditorState.changeFilter`) ; une modification forgée est rejetée par les pairs.
  « Proposer un changement » crée une suggestion qu'un admin accepte ou refuse.

**Matrice :**

| Id | Cas | Attendu |
|----|-----|---------|
| ACL-01 | admin déconnecte B, en ligne | B est coupé en moins de 2 s chez tous ; B voit « Vous avez été déconnecté par Alice » ; liste « Déconnectée par Alice à 10:02 » |
| ACL-02 | B, déconnecté, édite hors ligne puis réessaie | refusé ; son texte reste chez lui ; message clair |
| ACL-03 | laisser revenir B | B se reconnecte seul ; ses modifications en attente fusionnent ; rôle inchangé |
| ACL-04 | écrivain tente de déconnecter quelqu'un | option absente ; une opération forgée est rejetée par les pairs |
| ACL-05 | déconnecter la créatrice, ou soi-même | interdit (bouton absent, opération rejetée) |
| ACL-06 | deux admins : l'un déconnecte, l'autre laisse revenir, concurremment | ordre de la liste signée (pli par ancienneté, ADR 0017) ; résultat identique chez tous |
| ACL-07 | retirer B | définitif ; ré-inviter crée une nouvelle admission |
| ACL-08 | changer le rôle Écrit → Lit | B passe en lecture seule instantanément (barre grisée, raison affichée) |
| ACL-09 | figer la liste | plus d'arrivées ni de départs ; l'écriture continue |
| ACL-10 | transmettre le rôle de créatrice | prévu par l'ADR 0017 ; affichage mis à jour |
| LCK-01 | admin verrouille une sélection | hachures et cadenas chez tous ; étiquette « Verrouillé par Alice » |
| LCK-02 | écrivain tape dedans | rien n'est inséré ; popover « Cette partie est verrouillée… Proposer un changement » |
| LCK-03 | écrivain tape juste avant ou juste après la zone | autorisé ; la zone ne grandit pas (curseurs non collants) |
| LCK-04 | suppression d'un bloc qui englobe la zone | refusée en entier (pas de suppression partielle) |
| LCK-05 | coller par-dessus la zone, glisser-déposer, rechercher-remplacer tout | refusés sur la zone, appliqués ailleurs |
| LCK-06 | pair modifié qui envoie une modification dans la zone | rejetée par chaque pair honnête ; journal de sécurité |
| LCK-07 | admin édite dans la zone | autorisé |
| LCK-08 | admin lève le verrou | plus de hachures ; édition libre chez tous |
| LCK-09 | proposer un changement | suggestion visible chez les admins ; accepter → appliquée et marquée ; refuser → retirée |
| LCK-10 | verrou posé pendant qu'un pair hors ligne éditait la zone | à son retour, ses modifications dans la zone sont refusées et proposées en suggestion ; le reste fusionne |

### B4 · Projet multi-fichiers : ce que reçoit une personne qui rejoint

**Constat.** Aujourd'hui, seul `main.typ`, document racine, est synchronisé. Un projet réel
compte d'autres fichiers :
- des chapitres `.typ` ou `.md` ;
- des images, des PDF, des `.csv`, des `.bib` ;
- des polices ;
- des paquets `@preview` dans `.typstdeps/`.

**Modèle (ADR 0023, à faire valider par architect avant le code).**
- Un **index de projet** Automerge `{files: {chemin → {kind, url (texte) | hash (binaire), size,
  by, at}}}` fait foi pour l'arborescence.
- Chaque fichier texte est son propre document automerge-repo, référencé par `url`.
- Chaque fichier binaire est désigné par son hash BLAKE3 et transféré par le magasin `blob`
  (étape 4, avancé ici) : morceaux vérifiés, quotas, reprise.
- Les paquets `.typstdeps/` et les polices du projet sont des binaires comme les autres.
- Créer, renommer, déplacer et supprimer sont des opérations sur l'index. Une suppression va à la
  corbeille du projet ; elle est restaurable.

**Produit :**
- `ProjectIndex` (TS) : `add`, `rename`, `remove`, `restore` ;
- Go : `blob.Put`, `blob.Get` et l'échange libp2p (canal mux dédié), qui vérifie le hash avant
  l'écriture ;
- `Sidebar` : progression « Réception : 12 sur 40 fichiers, 3,2 Mo ».

**Matrice :**

| Id | Cas | Attendu |
|----|-----|---------|
| PRJ-01 | rejoindre un projet de 40 fichiers (texte, images, PDF, CSV, `.bib`, polices, `.typstdeps`) | les 40 arrivent ; arborescence identique ; hashes identiques ; le projet compile chez l'arrivant sans réseau (e2e + comparaison d'arborescence) |
| PRJ-02 | rejoindre puis couper le réseau à 50 % du transfert | reprise sans retransmettre ce qui est déjà vérifié ; « 20 sur 40 » affiché ; pas de fichier à moitié écrit visible |
| PRJ-03 | binaire falsifié par un pair modifié | hash refusé, fichier redemandé à un autre pair ; journal de sécurité |
| PRJ-04 | fichier ajouté après l'arrivée | apparaît chez tous, avec la bonne icône |
| PRJ-05 | A renomme `ch1.typ` pendant que B l'édite | B continue dans le même document (l'url ne change pas) ; les `#include` ne sont pas réécrits automatiquement, mais un avertissement « référence cassée » est affiché avec un lien de correction |
| PRJ-06 | A supprime un fichier pendant que B l'édite | B voit un bandeau « supprimé par A — Restaurer » ; ses frappes ne sont pas perdues (le document existe toujours, dans la corbeille) |
| PRJ-07 | A et B créent chacun `notes.md`, concurremment | aucun écrasement : deux fichiers, le second renommé `notes (B).md`, avec une note |
| PRJ-08 | A et B renomment le même fichier différemment | convergence déterministe (dernier écrivain par horloge de Lamport, puis acteur) chez tous ; l'autre nom figure dans l'historique |
| PRJ-09 | renommer un dossier entier | un seul déplacement atomique, pas N |
| PRJ-10 | chemins hostiles venus d'un pair (`../`, absolu, `\`, noms réservés Windows, NUL, 300 caractères) | refusés à l'arrivée (validation et bac à sable `os.Root`) ; fuzz du décodeur d'index |
| PRJ-11 | quotas | binaire de plus de 100 Mo refusé avec un message ; un projet de plus de 2 Go demande confirmation à l'arrivant avant téléchargement |
| PRJ-12 | lecteur qui rejoint | reçoit tout ; ne peut rien ajouter, renommer ni supprimer |
| PRJ-13 | fichier modifié hors d'Inkwell dans un sous-dossier, image remplacée sur le disque | B1 s'applique à tout fichier texte ; un binaire remplacé crée un nouveau hash, propagé |
| PRJ-14 | dépendance `@preview` absente du projet | message « paquet manquant : touying 0.7.4 — Ajouter au projet » ; jamais de téléchargement silencieux pendant une compilation |

## Cas croisés (les plus traîtres)

Chacun est un test e2e à 2 ou 3 instances, sauf mention ; « A » et « B » désignent deux personnes.

| Id | Cas | Attendu |
|----|-----|---------|
| X-01 | A et B tapent **au même caractère** en même temps | les deux textes présents, ordre déterministe identique chez les deux ; curseurs non sautés |
| X-02 | A supprime un paragraphe pendant que B tape dedans | la frappe de B survit (Automerge garde les insertions concurrentes) ; B voit le texte restant ; la bande signale la zone |
| X-03 | A met en gras `mot` pendant que B le supprime | pas de délimiteurs orphelins `**` laissés seuls : nettoyage à la convergence (règle : délimiteurs vides retirés) — à prouver en propriété sur 1 000 entrelacements |
| X-04 | A change le titre en niveau 2 pendant que B le passe en niveau 3 | un seul niveau final, identique chez les deux (pas `=====`) |
| X-05 | A annule (Ctrl+Z) une frappe ancienne après que B a écrit par-dessus | seule l'opération de A est inversée ; le texte de B reste (undo local, déjà testé à l'étape 1, étendu) |
| X-06 | **revenir à une version antérieure au verrou** | le verrou **reste** (il vit dans la liste signée, pas dans le texte) ; la zone revient au texte de la version **seulement si** la personne est admin. Un écrivain qui revient voit « La zone verrouillée n'a pas été modifiée », et le reste revient. |
| X-07 | revenir à une version où la zone verrouillée n'existait pas encore | le verrou reste ancré à ses curseurs. Si son texte disparaît, il devient « verrou vide » et est signalé à l'admin, qui le lève ou le replace. |
| X-08 | verrouiller, déverrouiller, reverrouiller 10 fois de suite, sur 2 pairs | état final identique ; chaque bascule est une entrée d'historique ; aucun verrou fantôme |
| X-09 | deux admins : l'un verrouille la zone, l'autre la déverrouille, concurremment | ordre de la liste signée (ADR 0017) ; même résultat chez tous ; l'interface dit qui a eu le dernier mot |
| X-10 | verrou qui chevauche un verrou existant | fusionnés en un seul (union), ou refusés avec un message — décision dans l'ADR 0022, testée dans les deux sens |
| X-11 | fusionner une variante qui modifie une zone verrouillée **depuis** sa création | la fusion par un admin applique tout ; par un écrivain, elle applique tout sauf la zone et propose le reste en suggestion |
| X-12 | variante créée par B, puis B est déconnecté | la variante reste visible ; sa fusion est possible par un admin ; les modifications de B faites **après** la déconnexion n'y entrent pas |
| X-13 | B est déconnecté puis revient pendant qu'il était hors ligne et a édité une zone verrouillée entre-temps | ACL-03 et LCK-10 s'appliquent ensemble : le hors-zone fusionne, la zone part en suggestion |
| X-14 | changement de rôle (Écrit → Lit) pendant que B tape | la frappe en cours **avant** l'opération signée est gardée, celle d'après est refusée ; B voit pourquoi |
| X-15 | modification extérieure du fichier qui touche une zone verrouillée | intégrée hors zone ; dans la zone, mise en suggestion et signalée (« modifié sur le disque dans une zone verrouillée ») |
| X-16 | fichier modifié dehors chez A **et** chez B (même fichier, deux machines) | les deux intégrations convergent ; aucune boucle d'écriture entre les deux disques (EXT-06 de chaque côté) |
| X-17 | arrivée de C pendant une présentation suivie | C reçoit tout (PRJ-01) et peut « suivre » ; la diapositive courante lui est donnée |
| X-18 | revenir à une version pendant une présentation | la diapositive recompilée se met à jour chez le présentateur sans quitter le plein écran |
| X-19 | 3 pairs : A ↔ B direct, B ↔ C relais, A et C jamais connectés | tout converge via B (texte, index, binaires, verrous, versions) |
| X-20 | horloge d'une machine décalée de +2 h | l'ordre de l'historique et des séances s'appuie sur la causalité (heads), pas sur l'heure ; l'heure affichée est marquée « selon l'appareil de X » |

## Ordre d'exécution

1. **Vague A** en parallèle (A1, A2, A3), puis A4.
2. **Conception B3 + B4** par architect (ADR 0021–0023), menée en même temps que la vague A.
3. **Vague B** : B1 ∥ B2, puis B4, puis B3 (dépend de B4 pour les verrous multi-fichiers).
4. **Vague C**, puis **vague D**.

Chaque tâche suit le même cycle :
1. un agent en worktree applique le TDD, un test par identifiant de cas ;
2. une revue (`go-reviewer` ou relecture TS) ;
3. la fusion dans `main` par le lead ;
4. `mise run ci`, `mise run e2e` et `mise run e2e:netsim` verts.

Note outillage : `wails3 generate bindings` est compilé avec Go 1.26 et avertit sur le code
Go 1.27. Il faut le recompiler avec la chaîne mise (Go 1.27), sous la tâche `fe:bindings`.

## Points de vigilance (non couverts ailleurs)

- Un formateur externe (typstyle, prettier) qui réécrit tout le fichier à chaque sauvegarde ne
  doit pas produire une intégration ligne à ligne bruyante. La différence est calculée par
  caractères, et la bande ne marque que le changement réel (EXT-07).
- Une personne avec plusieurs appareils doit être déconnectée sur tous ses appareils ; ACL-01 se
  teste aussi avec 2 appareils.
- Une variante qui inclut des fichiers binaires ajoutés (blob) dépend de l'étape 4 `blob`. En
  attendant, la variante ne porte que le texte, et l'interface le dit.
- Le menu Insérer ne doit jamais produire du Typst qui ne compile pas : chaque modèle est
  compilé en CI par `typst compile` dès la vague C.
