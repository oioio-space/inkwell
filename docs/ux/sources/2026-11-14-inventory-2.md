### A3. How it is rendered

- **Algorithm:** two stages: (1) line regions via `lineRegions` (`fe/store/merge.ts`, the same function that integrates outside edits, handles files too big for a full compare), (2) Myers word diff inside each region over tokens `[\p{L}\p{M}\p{N}_'’-]+ | \s+ | punctuation` (`words.ts:30`), runs merged, single-word replacement gets an underlined "inner" span, then `detectMoves` (blocks >= 4 words removed here and added elsewhere, similarity measured by shared words, `MOVE_MIN_WORDS`, `words.ts` ~l.173-208). **Source text only**, word granularity, with two exceptions: char underline for a one-word replacement, and whole-block "moved".
- **Inline mode** (`DiffInline.svelte`): one monospace flowing paragraph (`font: calc(15px * var(--text-zoom)) / 1.75 var(--font-mono)`, `white-space: pre-wrap`), **no line numbers, no gutter, no line-based layout**: added = `<ins>` with `--diff-add-bg/fg`, removed = `<del>` struck through `--diff-del-bg/fg` (`tokens.css:68-71`: light `#d4f0df/#0b4a2a`, `#fbd9d9/#7a0f18`; dark rgb with 22/24 % alpha), moved block = 1px inset outline + pill badge « déplacé », current hunk = 2px accent outline. Author = a pill chip with a dot in `--person-N` (`color-mix(... 22%)`) in front of each hunk, only for comparisons (`showAuthors={!req.session}`); tooltip on each run « Nom · date ». Unchanged text outside 3 context lines collapses into a grey separator « … N lignes inchangées … » (not expandable: no click handler on `.gap`).
- **Side-by-side mode**: `@codemirror/merge` `MergeView` (`DiffView.svelte:109-126`), read-only, line-based (`highlightChanges`, `gutter`, `collapseUnchanged {margin:3,minSize:4}`), custom theme using the same diff tokens; **its granularity differs from inline** (CodeMirror's own diff, line + its own intra-line), and the summary/attribution/moves of the inline mode do not apply (info line uses `sessionAt(blame, chunk.fromB)` for author only when attributed).
- **Dialog chrome:** native `<dialog>` modal, `--radius`, `box-shadow 0 12px 32px/25%`, backdrop `rgb(0 0 0/30%)`, header title `700 15px`, summary `400 15px`; sizes `min(1100px, 100vw-32px) x min(760px, 100vh-32px)` — a full modal even for a 1-word change; `ApplyDialog` is a second modal 760 wide stacked on it.
- **Performance:** diff runs **synchronously in `$derived`** on the main thread each time the dialog opens (`DiffView.svelte:35-39`); the *analysis* (sessions, blame) is in a Web Worker with a 30 s job limit (`analysis.ts JOB_MS`), blame is skipped when `ops x sessions > 1e8` (`BLAME_BUDGET`, `analysis.ts:46`) and everything is skipped above 512 Ki chars (`HUGE_TEXT = SLOW_CHARS`, `analysis.ts:56`; UI note `history.limited`). No virtualisation of the diff body (one DOM span per frag). Large-diff cost not measured here: not verified.

### B3. How the "git-like tree" is rendered

- **Per-row SVG, no global canvas.** Each `HistoryRow` draws its own `<svg width=laneX(maxLane)+14 height=64>` (`HistoryRow.svelte:88-114`): lane x = `14 + lane*16` px; **lane 0 is the main line** (grey `--fg-dim`, 2 px vertical strokes above/below the node); variants get lanes 1..n; `through[]` draws vertical strokes of open lanes across rows; fork/merge are cubic Bézier curves `M x1 y1 C x1 (y1+y2)/2 x2 (y1+y2)/2 x2 y2` from the variant lane to lane 0 (`curve`, line 25). Nodes: session = r6 circle, `--sidebar-bg` fill with **2.5 px stroke in the author's `--person-N`**; version = 12 px **diamond** (rotated rect) filled with lane colour; "now" = filled r6 circle `--accent-bg`; variant lane colour = `--person-(((lane*3)%8)+1)` (`color()`, line 21) — i.e. variants borrow the *people* palette.
- **Order** is "the document's causal order, never the clocks" (`graph.ts:50-51`): rows ordered by position in `analysis.order` (hash list of changes as applied on this replica) with tie-breakers `+0.1` (version), `+0.2+lane/100` (variant start), `+0.3+lane/100` (merge). The fork curve is attached to the *closest main-line row below* the variant start (`findLastIndex`, `graph.ts:132`), not to the exact base commit.
- **Row geometry:** `ROW_HEIGHT = 64` fixed (`history.svelte.ts:72`), **virtualised** by hand: spacer of `rows.length*64` px + `translateY(start*64)` window of rows [top/64 - 4, (top+h)/64 + 4] (`HistoryDrawer.svelte:19-20,154-160`). So the list scales; the graph cell width is computed per row from the lanes that cross it (rows may have different widths, so the text column does not align between rows: `width` derived per row, line 18-20).
- **No** branch labels, merge arrows, time axis or day separators; no grouping by day; sessions of one author are not collapsed; the whole drawer is 380 px wide so >2 lanes eat the text column (each lane = 16 px).
- Colours: `--fg-dim`, `--person-1..8` (`#e69f00 #56b4e9 #009e73 #f0e442 #0072b2 #d55e00 #cc79a7 #999999`, `fe/theme/tokens.css:101-108`), `--accent-bg`, `--selected-bg` (10 % grey), `--hover-bg`; abandoned variant row `opacity .55`; node stroke on `--sidebar-bg`: the yellow `#f0e442` ring on the light grey sidebar is low contrast (not measured).
- **Performance limits:** list virtual; `rows.findIndex` per key press and `rowOf` are linear; `buildGraph` is O(n log n) + one `findLastIndex` per variant; analysis (blame) in a worker, limited by `BLAME_BUDGET` (1e8 op x sessions ~ 15 s), skipped above 512 Ki characters (`analysis.ts:46-63`); the drawer then says « Ce document est trop volumineux pour suivre qui a écrit quoi : la liste des moments reste disponible » (when `limited`, `sessions` are still listed, but for `HUGE_TEXT` the analysis returns **no entries** (`tooBig`, `analysis.ts:56-65`), contradicting that sentence — not verified by running).

### B4. "Not synchronised" (W56): what is shared and what is local

Shared between people (evidence: stored inside the shared Automerge document):
- Named versions and automatic versions: `doc.meta.versions` (`versions.ts:50-67`); e2e HIS-06 asserts Bob sees « Version « Relecture DSI » … nommée par Alice » (`frontend/e2e/history.spec.ts:62-76`).
- The *list* of variants and their state (open/merged/abandoned): `doc.meta.variants` (`versions.ts:170-205`, `setState` 241-254); merge result reaches Bob (spec e2e l.166-172).
- Variant *content* is a separate Automerge document fetched by URL with a 15 s timeout (`history.svelte.ts:545-559`); the URL is added to the admitted set (`fe/net/scope.ts:36-54`, "interim root listing", cap 257 ids); `repo.find` only works if some peer holding the document is reachable (e2e ZZ-1/ZZ-2, `history.spec.ts:257-291`; ZZ-2 asserts availability after the creator leaves; result not verified by me). When missing the UI says « Cette variante est introuvable pour l'instant. » only after clicking.
- Claims (who is who) are written into the document as zero-text changes whose message is `inkwell:claim:{name,peer}` (`people.ts:78-97`).

Local to each device (evidence), hence the history can differ between people:
- **Session grouping depends on the viewer**: `personOfMine(myActors)` merges *my* actors into one "me", every other actor stays separate (`log.ts:164-176`); `myActors` is in `localStorage` (`fe/store/visit.ts:67`); and a session never spans "the last visit" of **this device** (`analysis.ts:76-80`, `past = pastOf(steps, since)`, `since` from `lastVisit` in localStorage). So two people can see different session boundaries, different row counts and different row ids (`s:<hash of first step>` changes when sessions split differently).
- **Row order** uses the order this replica applied changes (`log.ts` doc comment "in the order this replica applied them", `Step` list from `getChangesMetaSince`): the order of concurrent changes may differ per replica (not verified; Automerge canonical order of concurrent changes not checked).
- Time and "skewed" flags: authors' device clocks (`log.ts:90-95`).
- Names: claim -> presence name -> member list -> « Quelqu'un » (`people.ts:40-50`), so before a peer's claim lands the same actor can show as « Quelqu'un » on one side.
- Selected row, filters, "Qui a écrit quoi" toggle, "Variantes abandonnées" toggle, current variant being edited (`workspace.variant`), margin-strip "since" point: all local (`history.svelte.ts:84-112`). Spec VA-1 also says the current variant is a local setting (never synced), so that part is intended.
- Hidden: automatic versions are not listed for anyone (`v.auto`).
- `merge`/`abandon`/`reopen` are **last-writer-wins edits of `meta.variants[i].state`**, shared; concurrent merge by two people: the second call returns `merged:false` only if its replica already saw "merged" (`versions.ts:240-250`); two simultaneous merges are not prevented (not verified).
- Not in the document nor in any other store: nothing like "variant presence" (spec PD-5), "seulement sur l'ordinateur de X" hint.

What the specs say it should be: versions and variants are **documents and changes admitted by the ordinary rules, so identity and sync need no new format** (HI-8, `docs/architecture/spec.md` §6.11); variants are **shared, not private**: everyone sees all variants, "la liste des variantes est la même partout, hors ligne compris", content on demand with bounded prefetch (N46 paragraph "Synchronisation"); a named version is a **manifest of heads of the whole project** (index, each doc, blobs, main file) stored in the root doc with name, **note**, author, date (HI-3); history cursor order follows **local reception order, honestly labelled**, times are *declared* times (HI-10) — so the spec itself accepts per-device order; "Versions" is a sub-view of **Relire**, with `Relire` having 3 drawer destinations (coherence §6.2). W56's diagnosis ("ne se synchronise pas") is not written anywhere (`docs/exigences.md:74`, "à diagnostiquer"); the report/header plan only says "versions list with the history redesign W56" (`docs/plans/2026-11-13-report-and-header-design.md:108-109`).

1. **Someone else types in my view**: their text appears (patches applied one by one, `amPatches.ts`), **with no highlight at all** (no flash, no tint, no author mark). Only their caret (if their `file` is main.typ) with a name flag moves. My caret/selection is mapped (`selection.map(changes, 1)`).
2. **Someone types above my view**: text is inserted into the CodeMirror doc; nothing tells me. No scroll-anchor code exists: `grep -in scroll fe/editor/amSync.ts amPatches.ts` finds none; `setup.ts` mentions scroller only for sizing (l.39-42). Whether CodeMirror keeps my first visible line stable when text arrives above the viewport is **not verified** (no test covers it: no "scroll" in `amSync.test.ts`, `e2e/collab.spec.ts`, `e2e/netsim.spec.ts`). The plan requires it as a tested rule (CP2, `docs/plans/2026-11-10-collab-presence.md` §5.4: "a remote insert above the viewport must keep my first visible line on screen") — not built.
3. **Someone deletes text**: it disappears (a patch). No trace in the text, no marker; the "deleted" mark exists only in the **history** margin strip (triangle, `HistoryBars.svelte:156`) and diff.
4. **Someone's cursor is elsewhere**: no indicator if their head is off screen (no pill/arrow), no jump, no follow (CP3 not built; `docs/ux/sources/2026-11-14-inventory.md:§5` "Per-person caret follow/jump: absent").
5. **I was away and others edited**: when the app is reopened or the history analysis finishes, if `count > 0` the strip « Depuis votre dernière visite (hier 17:42) » appears above the text (`HistoryBars.svelte:149-167`), with legend (ajouté carré vert / modifié carré bleu / supprimé triangle rouge, or « N passages modifiés »), toggle « Par type | Par personne », button « Tout est vu »; the changed lines get a 7 px coloured bar in the margin (`changeGutter.ts:134`, `borderLeft 7px solid var(--change-color)`) and ticks on the minimap (`:151-159`) with title `label` « Nom, heure ». The marks are anchored by Automerge cursors and mapped through edits (`changeGutter.ts:~92-100`). Because the analysis re-runs 300 ms after every document change (`history.svelte.ts #schedule`), **live remote changes also accumulate as marks** until « Tout est vu » or until the visit point is rewritten (`saveVisit` on `pagehide`/hidden, `history.svelte.ts:197-205`). Colours: type mode `--success` (added), `--accent-bg` (modified), `--destructive` (deleted); person mode `--person-N`.
6. **« Qui a écrit quoi »** (drawer toggle) colours *all* text by author, for the whole document, not only recent changes; click a run -> opens the drawer on that session (`PICK` event). Disabled when the analysis is `limited`.
7. Not in the text at all: any indication of *who is typing now* beyond the caret flag (no "écrit…" state: presence has no `act`), idle/away fading, collision handling for same-offset carets, label flip/clamp at the top line.

**French labels:** `history.since`, `history.mark.added|modified|deleted`, `history.marks.*`, `history.colorby.*`, `history.seen` (`fr.json:687-694`, 568-571); caret flag text = the person's name only.

### D2. Data available now, without backend work (file:line)

- **Per change: author actor, time, deps, message, maxOp**: `A.getChangesMetaSince(doc, [])` (`fe/history/log.ts:47-64`). Actor -> person name via claims (`people.ts`), claims are written in the doc (`people.ts:78-97`). Time = the author's clock (claim).
- **Patches with ranges on arrival**: Automerge-repo `handle.on("change", ({patches, patchInfo}))` — the code already reads `patchInfo.source` (`history.svelte.ts:188-191`: `"change"` = local) and `amSync.ts` consumes `patches` to drive CodeMirror (`amPatches.ts:applyAmPatchesToCm`: insert/splice/del with character indexes). So at arrival time the **exact inserted/deleted ranges are known** (and `patchInfo.source` tells local vs remote). They are currently only applied, never decorated. Who wrote an arriving patch is **not in the patch**; it needs `A.getChangesMetaSince(doc, beforeHeads)` or `A.inspectChange`/`getChanges` on the new heads (available, same call as the history uses; cost per arrival not measured).
- **Attribution of text already there**: `Blame {spans: {from,to,s}, deletions: {at,text,by,owner}}` from `fe/history/track.ts` (worker, `analysis.ts`) incl. **where deleted text was and who deleted it** (`deletions`); recomputed within ~300 ms + worker time; skipped on large docs (`BLAME_BUDGET` 1e8, `HUGE_TEXT` 512 Ki chars, `analysis.ts:46-63`).
- **Last-seen heads per device**: `since` heads / `sinceAt` from `localStorage` (`fe/store/visit.ts:32-38`, used `history.svelte.ts:180-183`). **Per person** last-seen heads: not available (nobody broadcasts them; presence state has only name/file/anchor/head). Would need a presence field or a stored claim.
- **Presence fields**: `{name, file?, anchor?, head?}` only (`presence.ts:12`). Missing vs plan §5.1: `top`, `bottom` (visible range), `act` typing/active/idle, `focus`. So "who is typing now", "who is looking where", off-screen pills and follow need a wire change (small, Automerge-repo Presence state, no Go change; the plan lists it as CP0).
- **Colour slot**: FNV-1a of the peer id mod 8 (`ui/people.ts:personIndex`), PR1 replaces it by join-order slots (not built: `docs/plans/2026-11-13-pr1-presence.md` C4, "on `main`" status: not verified, header says implemented in a worktree). Tokens `--person-1..8` Okabe-Ito (`fe/theme/tokens.css:101-108`); **`--person-N-ink` and `--person-N-line` do not exist** (grep over `theme/`: none) although `docs/design/spec.md` §4.14 and plan §5.2 name them.
- Names: member list `Backend.Members()` + presence names + claims (`people.ts:40-50`).

### D3. How it is rendered

- Remote caret: `span.cm-remote-caret.cm-who-N` with `border-left: 2px solid var(--who)` and an absolutely positioned name span above the caret: `font 600 11px/1.6 var(--font-ui)`, **`color: #000` hard-coded** on `background: var(--who)` (`remoteCursors.ts` theme) — raw colour (UF-4 lint absent) and `#000` on `--person-5 #0072b2` / `--person-6 #d55e00` is low contrast (not measured here). Selection: `color-mix(--who 25%, transparent)`. Always visible (no 3 s fade, no hover, no flip below on the first line, no clamp to width, no collision handling); `aria-hidden`, widget `side: 1`, `pointer-events: none`.
- **Caret contrast**: 4 of 8 person colours below 3:1 as a caret on the light editor (`#f0e442` 1.32, `#e69f00` 2.25, `#56b4e9` 2.31, `#999999` 2.85) — `docs/reviews/2026-11-13-ux-ui-review.md:54`; mitigated only by the always-written name; planned as CP1 (`--person-N-line`).
- **Class-name clash (observed in code, visual effect not verified):** `blameMarks.ts` defines `.cm-who-N {background-color: color-mix(person-N 26%); box-shadow: inset 0 -2px …}` as a *base theme* loaded in every editor (`setup.ts:135,167`), and `remoteCursors.ts` uses the same class `cm-who-N` on the caret widget and the selection mark to set `--who`. So a remote caret span/selection probably also receives the blame background and underline even when « Qui a écrit quoi » is off. Needs a visual check.
- Change marks: line decoration `cm-changed cm-changed-{added|modified|deleted}` with `title` tooltip only (no visible label), 7 px bar (`changeGutter.ts:134`), minimap ticks; the person colour is injected as an inline `style` attribute (`changeGutter.ts:~76`) although the CSP is said to forbid inline style attributes (`remoteCursors.ts` comment: "Classes, not style attributes: the CSP forbids inline style attributes") — inconsistency, effect not verified.
- Sheet: `fresh` 4 s warning-colour flash per changed cell (`Grid.svelte:890`), `prefers-reduced-motion` handled at l.1026.
- No animation anywhere in the text area for arrivals (no fade, no pulse).

### D6. Observations (mine)
- The only real-time feedback for "someone changed my text" is the caret flag; the text itself changes silently, and a deletion leaves no trace — the opposite of W46's ask. The data (patches + `patchInfo.source`) to flash inserted ranges is already in the hands of `amSync.ts`; the missing piece is author lookup (`getChangesMetaSince` since the previous heads) and a decoration with a timed fade (Grid.svelte `fresh` shows the cue exists elsewhere).

### Gaps: which kinds of drift no check catches today
- **Spacing, type size, radius, shadow**: no numeric check anywhere (no token lint, no measured invariants, `tokens.test.ts` ignores them); only the 13 baselines, within 0.2 %/2 % pixel tolerance, on 6 screens.
- **Colour**: only `--hl-*` contrast is tested; raw colours (`#000` caret flag) are allowed; person-colour caret contrast (4 of 8 under 3:1) is documented but not tested.
- **Wrapping labels / overlap / clipping** (W53, « Les deux » on two lines): none (UF-2 and the planned one-line-label invariant are not built); only incidental in baselines at 1408 px, none at 360-720 px.
- **Missing control / wrong order**: no ARIA snapshot, no command-registry check; a button removed from the header would fail only the full-window baseline (header is part of it) and only by pixel ratio; for any surface without a baseline nothing fails.
- **Motion**: none (stills only; no enter/exit transitions exist to regress; two infinite animations exist against a recorded decision).
- **Surfaces without any visual guard**: sidebar content, history drawer, diff, apply dialog, share dialog, about, banners, toasts, spreadsheet, presenter, narrow and zoomed layouts, hover/focus states, the whole text-area collaboration layer.
- **Reference to compare against**: nothing links an implementation to an approved design (UF-8 not built; `docs/design/reference/` has only the W63 HTML); the `ux-walkthrough` method is a judgement without a reference picture.
- **Platform**: baselines are Chromium; the app runs in WebKitGTK; CI runs webkit with baselines named for chromium (not verified how); native window never compared.
- **Process**: `block_done.py` does not enforce the UX walkthrough that CLAUDE.md requires.
